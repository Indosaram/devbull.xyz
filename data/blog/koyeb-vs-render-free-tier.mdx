## 한눈에 보기

두 플랫폼 모두 Git으로 올리고 공개 주소를 받는 흐름은 비슷해요. 차이는 무료에서 인스턴스가 잠드는지, 어떤 데이터 계층을 같은 계정에서 붙일 수 있는지, 리전을 고를 수 있는지에 있어요. 데모와 학습이면 둘 다 시작할 수 있고, 세션을 로컬 디스크에 두면 어느 쪽이든 위험해요. 금액과 포함량은 문서를 보고, 여기서는 확인 항목만 다뤄요.

## 무료 플랜 비교 표

표는 인스턴스, 잠자기, 데이터, 로그를 개념으로 나눈 거예요. 칸의 구체 한도는 시점에 따라 바뀌니 가격 페이지와 무료 안내를 기준으로 고쳐 읽어요. 표에서 잠자기와 영구 저장이 갈리는 칸이 선택에 가장 큰 영향을 줘요. 둘 다 무료라고 해서 같은 운영 습관이 되는 것은 아니에요.

| 항목 | Koyeb 무료 플랜 | Render 무료 플랜 |
| --- | --- | --- |
| 성격 | 웹 서비스를 위한 무료 인스턴스 중심 | 웹 서비스와 정적 사이트를 함께 제공하는 무료 티어 |
| 유휴 시 동작 | 요청이 없으면 서비스를 내려 두고, 요청이 오면 다시 올라옴 | 일정 시간 요청이 없으면 잠들고, 다음 요청에서 깨어남 |
| 빌드 방식 | 저장소 연동, Dockerfile, 빌드팩 기반 빌드 | 저장소 연동, Dockerfile, 언어별 런타임 기반 빌드 |
| 인프라 코드 | 대시보드 중심에 CLI와 API를 함께 제공 | render.yaml 블루프린트로 선언적 관리 |
| 관리형 데이터베이스 | 서비스 형태로 제공하며 무료 범위는 플랜 확인 필요 | 무료 데이터베이스를 제공하되 보관 기간 제한이 있음 |
| 정적 사이트 | 별도 상품보다는 서비스로 서빙하는 방식 | 정적 사이트를 무료로 호스팅 |
| 커스텀 도메인 | 지원, 인증서 자동 발급 | 지원, 인증서 자동 발급 |
| 잘 맞는 경우 | 컨테이너 기반 API를 최소 설정으로 올릴 때 | 웹 서비스, 정적 사이트, 데이터베이스를 한곳에서 관리할 때 |

## Koyeb 무료 플랜의 특징

Koyeb 무료는 소규모 인스턴스와 제한된 리전, 유휴 시 내려가는 동작을 전제로 보는 편이 맞아요. 컨테이너나 빌드팩으로 올리고, 플랫폼이 주입하는 포트를 앱이 들어야 해요. 영구 볼륨이 제한되면 업로드와 SQLite를 로컬에 두면 안 돼요. 한도 초과 때 중단인지 과금인지는 가격 페이지를 봐요.

## Render 무료 플랜의 특징

Render 무료 웹 서비스도 유휴 뒤 잠들 수 있어서 첫 요청이 늦어져요. 정적 사이트, 웹 서비스, 데이터베이스를 제품 안에서 나누는 구성이 특징이에요. 무료 데이터베이스가 있는지는 시점의 무료 문서를 확인하고, 있어도 백업과 한도를 운영 기준으로 쓰지 마세요. 워커와 크론은 무료 포함 여부를 따로 봐요.

## 배포 절차: 두 플랫폼에서 공통으로 확인할 흐름

플랫폼이 달라도 저장소, 빌드, 시크릿, 헬스 체크 순서는 같아요. 이 네 가지가 맞으면 무료 한도와 별개로 배포 실패가 줄어요.

### 저장소와 브랜치 연결

배포할 브랜치를 하나로 정하고, 실험 브랜치가 운영 서비스에 붙지 않게 해요. 모노레포면 서비스 루트를 지정해요. 권한을 조직 범위로 열었다면 필요한 저장소만 남기는 편이 안전해요.

### 빌드와 시작 명령

로컬에서 되는 빌드와 시작 명령을 그대로 적어요. Dockerfile이 있으면 런타임 차이를 줄일 수 있어요. 시작 명령이 포그라운드에서 끝나 버리면 플랫폼은 프로세스가 죽은 것으로 봐요.

### 환경 변수와 시크릿

비밀 값은 저장소가 아니라 서비스 시크릿으로 넣어요. 무료 서비스라도 로그에 변수 값이 찍히지 않게 해요. 스테이징과 운영을 나누면 값 세트도 나누세요.

### 도메인, 헬스 체크, 로그

기본 도메인으로 먼저 응답을 확인하고, 사용자 도메인은 그다음 연결해요. 헬스 체크는 인증 없는 가벼운 경로로 둬요. 로그는 표준 출력으로 남겨야 화면에서 보여요.

## 상황별 선택 기준

컨테이너 이미지를 그대로 올리고 리전을 단순하게 쓰면 Koyeb 쪽을 먼저 봐요. 웹 서비스와 배치, 데이터 계층을 한 제품 안에서 시험하면 Render 구성을 봐요. 첫 응답 지연을 허용 못 하면 둘 다 무료만으로는 부족해요. 팀은 무료 한도보다 롤백과 환경 분리가 되는지로 고르세요.

## 주의할 점

무료 정책을 블로그 숫자로 외우지 마세요. 잠든 인스턴스를 장애로 오해하면 불필요한 재배포를 반복해요. 디스크에 둔 데이터는 재배포와 잠자기에 위험해요. 카드 등록 조건은 가입 화면과 가격 페이지를 같이 봐요.

## 자주 묻는 질문

상용 가능 여부, 잠자기, 데이터베이스, 느린 첫 응답이 대부분이에요.

### Koyeb 무료 플랜으로 상용 서비스를 운영해도 되나요?

학습과 낮은 트래픽 데모에는 쓸 수 있지만, 잠자기와 저장 한도 때문에 상용 상시 운영으로 두기는 어려워요. 최소 인스턴스를 유지해야 하면 유료 구성을 봐요. 한도는 가격 페이지가 기준이에요.

### Render 무료 웹 서비스가 잠들면 어떻게 되나요?

유휴 뒤 인스턴스가 내려가고, 다음 요청에서 다시 뜨면서 첫 응답이 늦어져요. 헬스 체크가 이 지연을 실패로 보면 재시작이 반복될 수 있어요. 지연을 허용 못 하면 잠자기를 끄는 유료 옵션을 검토해요.

### 두 플랫폼 모두 무료로 데이터베이스를 쓸 수 있나요?

가능 여부와 한도는 시점의 무료 문서가 달라요. 로컬 디스크를 데이터베이스로 쓰는 것은 두 플랫폼 모두 위험해요. 운영 데이터는 백업이 되는 관리형 쪽을 따로 두는 편이 안전해요.

### 무료 플랜에서 첫 응답이 느린 이유는 무엇인가요?

유휴 시 인스턴스가 내려갔다가 요청에 깨어나기 때문인 경우가 많아요. 앱 코드가 느린 것과 구분하려면 로그의 기동 시각과 요청 시각을 비교해요. 항상 깨어 있어야 하면 무료 구간 밖이에요.
