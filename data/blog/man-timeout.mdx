man timeout은 GNU coreutils timeout 명령의 매뉴얼을 여는 방법이에요. 시간 형식, 신호, 종료 상태를 기억 대신 그 페이지에서 확인하면 스크립트 분기가 안 어긋나요. 항목이 없다고 나오면 패키지가 빠졌거나 다른 timeout과 이름이 겹친 거예요. 아래는 페이지에서 먼저 볼 절과, 명령이 안 죽을 때 볼 옵션이에요.

## 한눈에 보기

timeout은 지정 시간 안에 끝나지 않은 명령에 신호를 보내요. 매뉴얼의 개요, 옵션, 종료 상태 절이 스크립트에 필요한 거의 전부예요. 기본 신호와 시간 초과 코드는 설치본마다 문구가 같을 수 있지만, 그 시스템의 man 페이지를 기준으로 해요. 애플리케이션 안의 시간 제한과 이 명령은 층이 달라요.

## man timeout 출력에서 먼저 볼 항목

SYNOPSIS로 옵션과 시간, 명령의 순서를 봐요. DURATION 설명에서 접미사와 접미사 생략 시 초라는 점을 확인해요. 신호 옵션과 강제 종료를 예약하는 옵션이 있는지 봐요. EXIT STATUS에서 시간 초과, 명령 없음, timeout 자체 실패가 어떻게 나뉘는지 적어요.

| 옵션 | 의미 | 쓰는 상황 |
| --- | --- | --- |
| `-s`, `--signal=SIGNAL` | 시간 초과 시 보낼 시그널을 지정해요. 기본은 TERM이에요. | 정상 종료 절차를 유도하고 싶을 때 |
| `-k`, `--kill-after=DURATION` | 지정한 시그널을 보낸 뒤 유예 시간이 지나도 살아 있으면 KILL을 보냅니다. | TERM을 무시하는 프로세스를 정리할 때 |
| `--preserve-status` | 시간 초과로 끝났더라도 명령의 종료 코드를 그대로 돌려줍니다. | 원래 실패 원인을 로그로 남기고 싶을 때 |
| `--foreground` | TTY 입력과 TTY 시그널이 필요한 실행을 허용해요. 이 모드에서는 COMMAND의 자식 프로세스에 타임아웃이 적용되지 않습니다. | 셸 프롬프트에서 대화형 명령을 감쌀 때 |
| `-v`, `--verbose` | 시그널을 보냈다는 사실을 표준 오류로 알려 줍니다. | 왜 종료됐는지 확인할 때 |

## 단계별로 man timeout 확인하기

man timeout을 실행해 항목 이름이 timeout(1)인지 봐요. 다른 절의 timeout이 먼저 나오면 절 번호를 지정해요. 페이지에서 시간 형식과 종료 상태를 메모하고, 스크립트의 분기와 비교해요. 옵션 이름이 스크립트와 다르면 그 버전 매뉴얼에 맞게 고쳐요.

## timeout의 동작 방식과 종료 코드

시간이 지나면 기본으로 TERM을 보내요. 자식이 무시하면 프로세스가 남으니, 매뉴얼의 강제 종료 예약 옵션을 봐요. 상태 유지 옵션이 없으면 시간 초과는 전용 종료 상태로 알려지는 것이 GNU 관례이고, 숫자는 man의 EXIT STATUS가 기준이에요. 명령이 스스로 끝난 코드와 섞이지 않게 분기를 나눠요.

| 종료 코드 | 의미 |
| --- | --- |
| 124 | 시간 초과로 종료되었습니다. `--preserve-status`를 쓰지 않았을 때의 기본값이에요. |
| 125 | `timeout` 자체가 실패했습니다. |
| 126 | COMMAND를 찾았지만 실행할 수 없었습니다. |
| 127 | COMMAND를 찾을 수 없었습니다. |
| 137 | COMMAND 또는 `timeout`이 KILL 시그널을 받았습니다. |

## 상황별 선택: 어떤 타임아웃 수단을 쓸까

셸에서 외부 명령을 감쌀 때는 timeout 명령이 맞아요. 서비스 유닛의 시작 한계는 systemd의 타임아웃 설정이 맞아요. 요청 처리는 애플리케이션 코드의 시간 제한이 맞아요. 바깥 안전망으로 timeout을 더 쓸 수는 있지만, 안쪽 제한과 누가 먼저인지를 적어요.

| 상황 | 권장 수단 | 이유 |
| --- | --- | --- |
| 배포 스크립트에서 외부 명령 하나를 감쌀 때 | `timeout` | 옵션과 종료 코드가 단순하고 이식성이 좋습니다. |
| 파이프라인이나 여러 명령을 묶어서 제한할 때 | `timeout`과 셸 실행을 조합 | 셸이 전체 묶음을 자식으로 실행하므로 한 번에 제한할 수 있습니다. |
| TERM을 무시하는 프로세스를 정리할 때 | `timeout -k` | 강제 종료 유예 단계를 둘 수 있습니다. |
| systemd로 관리되는 서비스 | 유닛의 실행 시간 제한 설정 | 서비스 관리자가 재시작 정책과 함께 제어해요. |
| 애플리케이션 내부의 외부 API 호출 | 언어나 클라이언트 라이브러리의 타임아웃 | 연결·읽기 단계별로 세밀하게 나눌 수 있습니다. |

## 주의할 점

셸 내장은 timeout이 실행하지 못해요. 파이프는 마지막 상태만 보일 수 있어서 전체를 제한하려면 묶어야 해요. 다른 패키지의 timeout과 PATH가 겹치면 man과 실행 파일이 다를 수 있어요. 손자 프로세스가 남으면 종료 코드가 나와도 자원이 남아요.

## 자주 묻는 질문

매뉴얼이 없을 때, 프로세스가 남을 때, 파이프, 종료 코드, 앱 타임아웃과의 차이가 반복돼요.

### man timeout을 실행했더니 매뉴얼 항목이 없다고 나옵니다. 왜 그런가요?

coreutils 매뉴얼 패키지가 없거나, 언어 로캘의 페이지가 없을 수 있어요. 절 번호를 지정해 1절을 열고, 실행 파일 which로 어떤 timeout인지 봐요. 최소 컨테이너에는 man 페이지가 빠져 있는 경우가 많아요.

### 타임아웃을 걸었는데 프로세스가 계속 살아 있습니다. 무엇을 확인해야 하나요?

대상이 TERM을 무시하는지, 손자가 다른 그룹에 있는지 봐요. 매뉴얼의 프로세스 그룹 옵션과 강제 종료 예약을 검토해요. 셸 내장을 감싼 것은 기대한 프로세스가 아닐 수 있어요.

### 파이프라인 전체에 타임아웃을 걸려면 어떻게 해야 하나요?

timeout은 하나의 명령을 감싸요. 파이프 전체를 하나의 셸 명령으로 묶어 그 셸을 timeout에 넘겨요. 파이프 상태 옵션도 같이 봐야 어느 단계가 실패했는지 알 수 있어요.

### 종료 코드 124와 137은 어떻게 다른가요?

GNU timeout에서 124는 시간 초과의 전용 상태로 쓰이는 값이 많아요. 137은 대개 KILL 신호로 끝난 상태예요. 상태 유지 옵션이 있으면 해석이 달라지니 man의 EXIT STATUS를 봐요.

### 애플리케이션 코드의 타임아웃과 timeout 명령 중 무엇을 써야 하나요?

요청 하나의 한계는 앱 코드가 이유를 알고 정리하기 좋아요. 프로세스 전체가 끝나지 않는 것을 막을 때는 timeout 명령이 바깥 안전망이에요. 둘을 같이 쓰면 어느 쪽이 먼저 끊는지 로그로 구분해요.
