Railway 무료 배포는 체험 크레딧으로 프로젝트를 올려 빌드와 도메인 흐름을 익히는 구간에 가까워요. 크레딧이 끝나면 서비스를 유지하려면 유료 전환이 필요할 수 있어요. 포함 범위와 금액은 가격 문서가 기준이라 여기에는 숫자를 적지 않아요. 아래는 체험과 유료의 차이, 배포 절차, 요금이 생기는 시점이에요.

## 한눈에 보기

체험은 크레딧을 쓰며 배포를 시험하는 쪽이고, 유료는 플랜과 사용량으로 이어 가는 쪽이에요. Git 연동, CLI, Docker 모두 체험 중에도 쓸 수 있는 경우가 많지만 조건은 문서를 봐요. 데이터베이스와 볼륨은 앱을 지워도 남을 수 있어요. 사용량 화면에서 체험 잔량을 봐요.

## 무료 배포와 유료 전환의 차이

표는 시작 방식, 과금 기준, 지속성, 적합한 용도를 나눈 거예요. 체험은 학습과 데모, 유료는 운영과 팀 협업에 맞아요. 크레딧이 떨어지면 제한될 수 있으니 운영 서비스를 체험만으로 설계하지 않아요.

| 항목 | 무료 체험 | 유료 사용 |
| --- | --- | --- |
| 시작 방식 | 무료 체험 크레딧으로 프로젝트 배포 | 플랜과 결제 조건에 따라 사용 |
| 과금 기준 | 제공된 체험 범위 안에서 사용 | 사용량과 플랜 조건에 따라 과금 |
| 지속성 | 크레딧 소진 시 제한 가능 | 플랜 유지 시 지속 운영 |
| 적합한 용도 | 학습, 데모, 배포 흐름 검증 | 운영 서비스, 팀 협업, 안정적 운영 |

## Railway 무료 배포 절차

저장소 준비부터 체험 상태 점검까지 한 바퀴 돌려 보면 유료 전환 전에 막히는 지점이 보여요.

### 저장소와 프로젝트 준비

올릴 브랜치와 시작 명령을 로컬에서 확인해요. 앱이 주입된 포트를 듣는지 봐요. 비밀은 저장소에 넣지 않아요.

### 프로젝트 생성과 저장소 연결

프로젝트를 만들고 저장소와 브랜치를 연결해요. 저장소 없이도 CLI로 시험할 수 있어요. 자동 배포 브랜치를 시험용으로 한정해요.

### 환경 변수와 빌드 설정 확인

빌드와 시작 명령을 서비스에 적고, 필요한 변수를 넣어요. 체험이어도 빠진 변수는 시작 실패로 보여요. 운영 값과 시험 값을 섞지 마세요.

### 배포 실행과 로그 확인

푸시나 CLI로 배포하고 빌드 로그와 시작 로그를 나눠 봐요. 헬스 체크 실패는 빌드 성공 뒤에 나와요. 첫 오류만 고치고 다시 배포해요.

### 도메인과 공개 범위 설정

기본 도메인으로 응답을 확인한 뒤 공개 범위를 정해요. 인증 없는 API라면 시험 데이터만 두세요. 사용자 도메인은 체험이 유지될 때 연결해도 되고, DNS는 안내된 레코드만 넣어요.

### 무료 체험 상태 점검

사용량 화면에서 크레딧과 서비스별 점유를 봐요. 안 쓰는 서비스와 볼륨을 지워요. 잔량이 얼마 안 남으면 유료 전환이나 삭제를 미리 정해요.

## 배포 방식 비교

표는 GitHub, CLI, Docker의 시작 지점과 확인할 점을 나눈 거예요. 체험 중에도 방식 차이는 같고, 과금만 체험 범위 안인지가 달라요. 이미지 크기와 포트는 Docker에서 특히 확인해요.

| 배포 방식 | 시작 지점 | 장점 | 확인할 점 |
| --- | --- | --- | --- |
| GitHub 연동 | 원격 저장소 | 푸시할 때 자동 배포 가능 | 브랜치와 빌드 설정 |
| Railway CLI | 로컬 터미널 | 현재 디렉터리를 빠르게 배포 | 로그인과 프로젝트 연결 |
| Docker 이미지 | Dockerfile 또는 이미지 | 런타임을 직접 제어 | 이미지 크기와 포트 설정 |

## 상황별 선택 기준

학습이면 체험으로 한 바퀴 돌리고 지워요. 데모를 며칠 유지하려면 잔량과 볼륨을 매일 봐요. 팀 운영은 유료와 환경 분리를 전제로 해요. 데이터베이스가 필요하면 체험 포함인지 문서를 본 뒤 붙이고, 지우기 전에 덤프해요.

## 주의할 점

무료로 계속된다는 옛 글을 그대로 믿지 마세요. 서비스를 멈춰도 볼륨이 남으면 사용량이 줄지 않을 수 있어요. 체험 정책은 가격 문서가 기준이에요. 시크릿이 로그에 찍히면 값을 교체해요.

## 자주 묻는 질문

계속 무료인지, GitHub, 데이터베이스, 요금 시점이 반복돼요.

### Railway는 정말 무료로 계속 배포할 수 있나요?

체험 크레딧이 있는 동안의 시험으로 보는 편이 맞아요. 크레딧이 끝나면 유지하려면 유료 조건이 필요할 수 있어요. 현재 기준은 가격 문서예요.

### 무료 체험 중에도 GitHub 연동 배포가 가능한가요?

연결 권한이 있고 대상 브랜치가 맞으면 체험 중에도 푸시 배포를 쓸 수 있어요. 한도에 걸리면 배포가 막힐 수 있어요. 권한과 브랜치를 먼저 확인해요.

### 무료 체험 중 데이터베이스도 사용할 수 있나요?

프로젝트에 데이터베이스 서비스를 붙일 수 있는지는 체험 포함 범위를 문서로 확인해요. 붙이면 사용량과 볼륨이 같이 줄어요. 지우기 전에 백업해요.

### 요금이 발생하는 시점은 언제인가요?

체험 범위를 넘거나 유료 플랜으로 넘어간 뒤 사용량과 플랜 조건에 따라 청구가 생길 수 있어요. 정확한 시점은 가격 문서와 청구 화면을 봐요. 알림이 있으면 켜 두세요.
