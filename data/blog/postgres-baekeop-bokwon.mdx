Postgres 백업 복원은 덤프를 다시 넣는 일과, 데이터 디렉터리를 되살린 뒤 WAL을 재생하는 일이 달라요. 백업 파일만 있다고 장애 직전까지 돌아오는 것은 아니에요. 복원 연습과 복원 후 검증이 없으면 파일은 있어도 절차가 없어요. 아래는 논리, 물리, PITR의 복원 순서예요.

## 한눈에 보기

논리 백업은 pg_dump와 pg_dumpall, 복원은 pg_restore나 psql이에요. 물리 백업은 pg_basebackup이고, PITR은 그 베이스에 WAL을 이어 붙여요. 복원 대상 버전과 역할, 확장이 맞아야 앱이 붙어요. 운영 인스턴스에 복원 명령을 잘못 실행하면 데이터를 덮어요.

## 백업 방식 비교 표

표는 도구, 단위, 장점, 주의, 적합한 상황을 나눈 거예요. 논리 백업은 객체 단위로 옮기기 좋고, 물리는 클러스터 전체를 같은 계열로 되살릴 때 맞아요. PITR은 WAL이 끊기면 목표 시점까지 못 가요.

| 항목 | 논리 백업 | 물리 백업 | PITR |
|---|---|---|---|
| 주요 도구 | `pg_dump`, `pg_dumpall` | `pg_basebackup` | 베이스 백업과 WAL 아카이브 |
| 백업 단위 | 데이터베이스, 스키마, 테이블 | 클러스터의 데이터 파일 | 베이스 백업 시점과 WAL 구간 |
| 복원 단위 | 객체를 다시 생성하고 데이터를 적재 | 데이터 디렉터리 교체 | 베이스 백업 복원 후 WAL 재생 |
| 장점 | 특정 객체만 다루기 쉽고 형식을 검토하기 좋아요 | 전체 인스턴스를 한 흐름으로 복구하기 좋아요 | 장애 직전이나 특정 시점으로 되돌릴 수 있어요 |
| 주의점 | 대용량에서는 시간이 오래 걸릴 수 있어요 | 서버 설정과 권한, 저장 공간을 함께 봐야 해요 | WAL 보관이 끊기면 목표 시점 복구가 어려워요 |
| 적합한 상황 | 개발 데이터 이관, 단일 DB 백업 | 전체 클러스터 백업, 재해 복구 | 데이터 오입력, 특정 시점 복구 |

## 단계별 백업과 복원 방법

백업 종류에 맞춰 복원 도구를 고르고, 빈 곳이나 멈춘 인스턴스에서 연습해요.

### 논리 백업: pg_dump와 pg_dumpall

한 데이터베이스는 pg_dump, 역할까지 포함한 클러스터 논리는 pg_dumpall을 검토해요. 형식은 선택 복원이 필요하면 커스텀 형식을 봐요. 덤프에 비밀이 들어가면 보관 권한을 좁혀요.

### 논리 복원: pg_restore와 psql

커스텀 형식은 pg_restore, 평문 SQL은 psql로 넣어요. 빈 데이터베이스에 넣고, 기존 운영에 덮어쓸지는 별도 결심이 필요해요. 복원 중 오류를 무시하고 넘어가면 테이블이 빠져요.

### 물리 백업: pg_basebackup

데이터 디렉터리 복사에 가까워서 대상 서버의 버전과 경로, 권한을 같이 봐요. 복제 연결 권한이 있어야 떠요. 백업이 혼자 기동할 수 있게 WAL이 따라붙었는지 확인해요.

### 물리 복원과 PITR

데이터 디렉터리를 준비한 뒤 복구 설정으로 WAL을 재생해요. 목표 시점은 아카이브가 그 시점까지 있을 때만 가능해요. 재생이 끝나면 타임라인과 앱 접속을 확인한 뒤에 트래픽을 열어요.

## 상황별 선택 기준

개발 데이터 이관은 논리 복원이 맞아요. 서버 전체 장애는 물리 복원을 준비해요. 잘못된 갱신을 특정 시점으로 되돌리려면 PITR이에요. 하나만 두지 말고, 복구 목표에 없는 방식은 추가해요.

## 주의할 점

백업을 운영 디스크에만 두지 마세요. 메이저가 다르면 물리 백업은 바로 기동하지 못해요. 복원 명령을 운영 포트에 연결하면 살아있는 데이터를 덮을 수 있어요. WAL 아카이브 실패를 알림 없이 두면 복구 때야 알아요.

## 복원 후 검증

앱 계정으로 필요한 테이블을 읽고, 최근 행과 시퀀스, 확장, 역할이 있는지 봐요. 크기만 같고 제약이나 인덱스가 빠졌는지도 확인해요. 쓰기 가능한 복원본에서 시험 쓰기를 한 뒤 운영으로 열어요. 검증 절차를 백업 잡과 같이 문서에 남겨요.

## 자주 묻는 질문

두 도구의 차이, 파일만으로 완전 복구인지, 복원 후 확인이 핵심이에요.

### pg_dump와 pg_basebackup은 무엇이 다른가요?

pg_dump는 객체를 다시 만드는 논리 백업이고, pg_basebackup은 데이터 파일 중심의 물리 백업이에요. 복원 도구와 버전의 요구가 달라요. 이관은 논리, 서버 복구는 물리를 먼저 검토해요.

### 백업 파일만 있으면 항상 완전 복구가 가능한가요?

논리 덤프는 덤프 시점의 내용을 다시 만들 수 있어요. 그 이후 트랜잭션은 WAL이 있어야 해요. 설정 파일과 역할이 덤프 범위 밖이면 따로 필요해요.

### 복원 후에는 무엇을 확인해야 하나요?

앱 계정의 읽기, 최근 데이터, 확장, 시퀀스, 쓰기가 되는지 봐요. 오류 로그에 누락된 객체가 있는지도 봐요. 검증 전에 트래픽을 열지 마세요.
