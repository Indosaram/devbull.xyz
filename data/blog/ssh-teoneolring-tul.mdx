SSH 터널링 툴은 대부분 OpenSSH 클라이언트의 포트 포워딩으로 시작하고, 부족할 때 점프 호스트나 재연결, 라우팅 도구를 더해요. 로컬, 원격, 동적 포워딩은 누가 포트를 듣는지가 달라요. 도구를 늘리기 전에 서버가 포워딩을 허용하는지를 봐요. 아래는 OpenSSH 구성, ProxyJump, 끊김 대처예요.

![ssh 터널링 툴 기초 정리 소제목 카드. 한눈에 보기, 터널링 방식 비교 표, OpenSSH로 로컬·원격·동적 포워딩 구성하기, 점프 호스트와 ProxyJump 사용하기](/static/images/ssh-teoneolring-tul/diagram.webp)

## 한눈에 보기

기본 툴은 ssh 명령과 ssh_config예요. 터널은 그 세션이 살아있는 동안만 유지돼요. 점프 호스트가 필요하면 ProxyJump로 중간 서버를 거칠 수 있어요. autossh나 sshuttle 같은 도구는 재연결이나 경로 단위 전달이 필요할 때 검토하고, 정책이 금지하면 쓰지 않아요.

## 터널링 방식 비교 표

표는 로컬, 원격, 동적 포워딩의 옵션과 듣는 위치를 나눈 거예요. 대상이 하나면 로컬, 내 쪽을 밖에 잠깐 열면 원격, 여러 대상은 동적이에요. 방향이 바뀌면 방화벽과 서버 설정도 바뀌어요.

| 방식·도구 | 주 용도 | 핵심 옵션 | 서버 쪽 확인 |
|---|---|---|---|
| OpenSSH 로컬 포워딩 | 내 컴퓨터의 포트를 원격 내부 대상으로 연결 | `-L` | `AllowTcpForwarding` |
| OpenSSH 원격 포워딩 | SSH 서버 쪽 포트를 내 쪽 대상으로 연결 | `-R` | `GatewayPorts`, 방화벽 |
| OpenSSH 동적 포워딩 | 로컬 SOCKS 프록시로 여러 대상 접근 | `-D` | `AllowTcpForwarding` |
| ProxyJump | 점프 호스트를 거쳐 최종 서버 접속 | `-J`, `ProxyJump` | 중간 서버의 SSH 허용 |
| autossh | SSH 세션을 감시하고 끊기면 재시작 | `autossh` 실행 옵션 | SSH 접속 정책 |
| sshuttle | SSH를 통한 네트워크 단위 트래픽 전달 | `sshuttle` 실행 옵션 | 로컬 권한, 원격 환경 |

## OpenSSH로 로컬·원격·동적 포워딩 구성하기

세 방식 모두 SSH 계정과 키가 먼저예요. 포트가 이미 쓰이면 다른 포트를 골라요.

### 로컬 포워딩

내 포트와 SSH 서버가 보는 대상을 로컬 포워딩으로 연결해요. 클라이언트는 내 포트로 접속해요. 대상 이름의 localhost는 서버 기준이에요.

### 원격 포워딩

서버가 들을 포트를 내 서비스에 연결해요. 다른 장비에서 열려면 서버 설정 허용이 필요해요. 끝나면 세션을 닫아요.

### 동적 포워딩

내 포트를 SOCKS 프록시로 만들어요. 앱이 프록시를 쓰도록 설정해야 트래픽이 들어가요. VPN처럼 모든 경로를 바꾸지는 않아요.

## 점프 호스트와 ProxyJump 사용하기

중간에 배스천이 있으면 ProxyJump로 최종 호스트까지 연결해요. 키와 사용자는 호스트마다 설정 파일에 나눌 수 있어요. 점프 서버에 불필요한 포워딩 권한을 열지 마세요. 에이전트 전달은 필요할 때만 켜요.

## 연결 유지와 네트워크 라우팅 도구

세션이 유휴로 끊기면 서버와 클라이언트의 유지 옵션을 문서 기준으로 맞춰요. 자동 재연결이 기본은 아니라서, 필요하면 autossh 같은 감시 도구를 검토해요. 서브넷 전체를 터널로 보내야 하면 sshuttle 같은 도구가 있는지 정책을 먼저 봐요. 도구가 늘수록 누가 포트를 여는지 문서에 적어요.

## 상황별 선택 기준

데이터베이스 하나만 보면 OpenSSH 로컬 포워딩으로 충분해요. 여러 내부 사이트는 동적 포워딩이에요. 배스천 뒤는 ProxyJump예요. 상시 경로와 자동 재연결이 요구되면 추가 도구를 검토하되, 운영 서버의 포워딩 정책 밖으로 나가지 않아요.

## 주의할 점

터널 포트는 그 머신의 다른 계정도 쓸 수 있어요. 원격 포워딩을 모든 주소에 열지 마세요. known_hosts 확인을 끄지 마세요. 재연결 도구가 옛 세션을 중복으로 열면 포트 충돌이 나요.

## 자주 묻는 질문

OpenSSH만으로 되는지, 방향, 동적 포워딩, 끊김이 반복돼요.

### ssh 터널링 툴은 OpenSSH만으로 충분한가요?

대상이 분명한 포트 전달은 OpenSSH로 충분해요. 자동 재연결이나 네트워크 단위 전달이 필요하면 별도 도구를 검토해요. 도구를 더하기 전에 서버 허용 정책을 봐요.

### 로컬 포워딩과 원격 포워딩은 어떻게 구분하나요?

로컬은 내 컴퓨터가 포트를 듣고 서버가 대상에 접속해요. 원격은 서버가 듣고 내 컴퓨터가 대상에 접속해요. 누가 듣는지가 이름보다 정확해요.

### 동적 포워딩은 언제 쓰나요?

대상 호스트가 여러 개라 포트 규칙을 늘리기 어려울 때 써요. 앱이 SOCKS를 지원해야 해요. 지원하지 않는 앱은 터널을 타지 않아요.

### 터널이 자주 끊기면 어떻게 해야 하나요?

세션이 유휴로 끊기는지, 네트워크가 끊기는지 로그로 나눠요. 유지 옵션과 서버의 유휴 제한을 맞춰요. 그래도 필요하면 재연결 도구를 검토하되 중복 세션을 막아요.
