## 한눈에 보기

ECR 저장소는 이미지를 보관하는 곳이고, 이미지 리소스는 그 저장소에 올릴 산출물을 만들어요. awsx가 둘을 감싸 주지만, 빌드는 Pulumi를 실행하는 머신에서 일어나요. 태그를 매번 바꾸면 어떤 배포가 어떤 이미지인지 추적이 어려워져요. 레지스트리 문서의 권한과 수명 정책도 같이 봐야 해요.

## 비교 표

표는 Image와 Repository가 만드는 것, 필요한 도구, 언제 쓰는지로 나뉜 거예요. 저장소만 있고 빌드는 CI가 하면 Repository 쪽이 맞아요. 프로그램 안에서 빌드와 푸시까지 끝내려면 Image예요. 둘을 한 스택에서 쓰면 누가 태그를 소유하는지 정해요.

| 항목 | awsx.ecr.Image | 직접 빌드 후 참조 |
| --- | --- | --- |
| 빌드 실행 | Pulumi 업데이트 과정에서 Docker 빌드와 푸시를 함께 처리해요. | CI나 로컬에서 빌드와 푸시를 먼저 끝내요. |
| Pulumi가 아는 값 | `imageUri` 출력으로 이미지 위치를 참조해요. | 이미지 URI나 다이제스트를 변수로 전달해요. |
| 적합한 상황 | 작은 서비스나 Pulumi 안에서 배포 흐름을 단순화할 때 좋아요. | 빌드 캐시, 보안 스캔, 다중 플랫폼 빌드를 CI에서 다룰 때 좋아요. |
| 주의점 | 실행 환경의 Docker와 AWS 권한을 확인해야 해요. | 이미지가 먼저 존재해야 하고 태그 불변성을 따로 관리해야 해요. |

## 단계별 방법

저장소를 둘지 이미지를 빌드할지를 정하고, 실행 환경의 빌드 도구와 자격 증명을 확인해요. repositoryUrl에는 저장소가 알려 주는 레지스트리 주소를 넣어요. 미리보기에서 이미지 푸시와 저장소 생성이 구분되는지 봐요. 배포 뒤 태그가 기대한 값인지 출력으로 확인해요.

```
import * as awsx from "@pulumi/awsx";

const repo = new awsx.ecr.Repository("app-repo");

const image = new awsx.ecr.Image("app-image", {
  repositoryUrl: repo.url,
  path: "./app",
});

export const imageUri = image.imageUri;
```

## 상황별 선택

CI가 이미 이미지를 만들면 Pulumi는 저장소와 태그만 받아요. 개발 스택에서 빠르게 붙이려면 Image 컴포넌트가 짧아요. 운영은 재현되는 태그를 CI가 만들고 Pulumi는 그 태그를 참조하는 편이 안전해요. 로컬 빌드에 의존하면 실행하는 사람마다 결과가 달라져요.

## 주의할 점

Docker 데몬이나 빌드 도구가 없으면 Image 생성 단계에서 실패해요. 자격 증명이 푸시 권한이 없으면 저장소는 생겨도 이미지가 없어요. 최신 태그만 쓰면 롤백할 이전 이미지를 특정하기 어려워요. 저장소 정책을 넓게 열지 마세요.

## 자주 묻는 질문

두 리소스의 차이, 주소에 넣을 값, 빌드 도구, 태그 관리가 핵심이에요.

### awsx.ecr.Image와 awsx.ecr.Repository는 어떻게 다른가요?

Repository는 레지스트리 저장소를 만들고, Image는 빌드해서 그 저장소에 푸시하는 쪽이에요. 빌드를 밖에서 하면 Repository와 태그 참조만으로 충분해요. 옵션 이름은 설치한 awsx 문서를 따라요.

### repositoryUrl에는 무엇을 넣어야 하나요?

저장소 리소스가 출력하는 레지스트리 주소를 넣어요. 계정과 리전이 다른 주소를 손으로 붙이면 푸시가 다른 곳으로 가거나 실패해요. 출력으로 연결하는 편이 안전해요.

### Pulumi 실행 환경에 Docker가 꼭 필요한가요?

Image처럼 그 자리에서 빌드하는 경로면 빌드 도구가 필요해요. 이미 올라간 태그만 참조하면 실행 환경에 빌드 데몬이 없어도 돼요. CI에 도구를 둘지 로컬에 둘지 팀에서 정해요.

### 이미지 태그가 계속 바뀌면 어떻게 관리하나요?

배포마다 고유하고 다시 빌드해도 같은 입력이면 같은 태그가 되게 규칙을 정해요. 스택 출력에 지금 태그를 남겨 롤백할 값을 찾게 해요. 움직이는 최신 태그만 운영에 쓰지 마세요.
