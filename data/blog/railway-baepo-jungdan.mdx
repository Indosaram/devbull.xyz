## 한눈에 보기

배포 한 건이 중단돼도 이전 배포가 트래픽을 받는 경우가 있어요. 서비스 자체를 중지하면 공개 주소의 응답이 멈출 수 있어요. 빌드 구간의 오류와 배포 구간의 헬스 체크를 로그에서 나눠요. Git 푸시 후 배포가 안 생기면 연결과 브랜치부터 봐요.

## railway 배포 중단 원인 비교

표는 빌드 중단, 배포 단계 중단, 사용자 취소, 서비스 중지, 자동 배포 미실행을 확인 위치와 대응으로 나눈 거예요. 첫 오류 지점을 로컬에서 같은 명령으로 재현하면 빌드 문제가 빨리 줄어요. 포트와 헬스 경로 불일치는 빌드 로그가 깨끗해도 나요.

| 구분 | 확인 위치 | 흔한 원인 | 대응 |
|---|---|---|---|
| 빌드 단계 중단 | 배포 로그의 빌드 구간 | 의존성 설치 실패, 빌드 명령 오류, 환경 변수 누락 | 첫 오류 지점을 찾고 로컬에서 같은 명령을 재현해요 |
| 배포 단계 중단 | 배포 로그와 헬스체크 설정 | 포트 바인딩 오류, 헬스체크 경로 불일치, 시작 지연 | 앱이 외부 인터페이스에 바인딩되는지와 응답 경로를 확인해요 |
| 사용자 취소 | 배포 목록의 상태 | 수동 취소, 새 배포로 대체 | 필요한 배포인지 확인한 뒤 다시 실행해요 |
| 서비스 일시 중지 | 서비스 설정과 상태 | 수동 중지, 사용량 한도, 플랜 설정 | 서비스 범위와 사용량을 확인하고 필요한 경우 다시 활성화해요 |
| 자동 배포 미실행 | GitHub 연결과 웹훅 | 브랜치 불일치, 저장소 권한 변경, 웹훅 비활성 | 저장소 연결과 대상 브랜치를 다시 확인해요 |

## 배포 중단 상황을 확인하는 단계별 방법

배포 목록에서 상태가 취소인지, 실패인지, 빌드 중 멈춤인지 봐요. 로그를 빌드 구간과 시작 구간으로 나눠 첫 오류를 적어요. 헬스 체크 경로와 앱이 듣는 포트를 비교해요. GitHub 연결, 대상 브랜치, 웹훅이 살아 있는지도 봐요. 사용량 한도나 플랜으로 서비스가 멈춘 것은 배포 로그가 아니라 서비스 상태에 있어요.

## 상황별 선택: 재배포, 롤백, 일시 중지

방금 커밋이 깨졌고 이전 배포가 정상이면 롤백이 먼저예요. 환경 변수만 빠졌으면 값을 넣고 재배포해요. 비용을 멈추려고 서비스를 일시 중지하면 트래픽도 멈춘다는 점을 팀에 알리세요. 새 배포가 실패해도 이전 배포를 유지하는 설정인지 문서에서 확인한 뒤 실험해요.

## 주의할 점

배포 취소와 서비스 중지를 같은 말로 쓰지 마세요. 롤백 뒤 환경 변수가 새 값이면 증상이 남을 수 있어요. 자동 배포가 겹치면 중단된 것처럼 보여도 새 배포가 이전 것을 대체한 것일 수 있어요. 한도 중지는 코드 수정으로 해결되지 않아요.

## 자주 묻는 질문

기존 서비스가 멈추는지, 로그가 깨끗한 중단, 푸시 후 미실행, 중지와의 차이, 롤백 순서가 반복돼요.

### Railway에서 배포를 중단하면 기존 서비스도 멈추나요?

진행 중인 새 배포만 멈추면 이전 배포가 계속 받는 경우가 많아요. 서비스 자체를 중지하면 응답이 멈출 수 있어요. 배포 상태와 서비스 상태를 따로 봐요.

### 빌드 로그에 오류가 없는데 배포가 중단될 수 있나요?

가능해요. 시작 후 헬스 체크 실패, 포트 바인딩, 시작 지연이 배포 단계 중단에 들어가요. 런타임 로그와 헬스 경로를 봐요.

### GitHub 푸시 후 배포가 시작되지 않으면 무엇을 확인해야 하나요?

저장소 연결, 대상 브랜치, 자동 배포 스위치, 웹훅 권한을 봐요. 다른 브랜치에 푸시했을 수 있어요. 연결이 끊기면 푸시는 성공해도 배포가 안 생겨요.

### 배포 중단과 서비스 일시 중지는 어떻게 다른가요?

배포 중단은 그 배포 시도가 끝난 것이고, 일시 중지는 서비스 실행을 멈춘 거예요. 확인 위치가 배포 목록인지 서비스 상태인지가 달라요. 사용량 한도로 중지된 것은 코드 재배포만으로 안 풀릴 수 있어요.

### 롤백과 재배포 중 무엇을 먼저 해야 하나요?

이전 배포가 정상이고 새 변경이 원인이면 롤백이 먼저예요. 설정 값만 고치면 되는 문제면 값을 맞춘 재배포예요. 원인을 적기 전에 여러 번 재배포하면 로그가 섞여요.
