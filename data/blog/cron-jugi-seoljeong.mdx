## 한눈에 보기

사용자 작업은 `crontab -e`로 편집하고 `crontab -l`로 읽어요. 필드 순서는 분, 시, 일, 월, 요일이고 그 뒤에 명령이 와요. 시스템 작업은 `/etc/crontab`이나 `/etc/cron.d/`에 두며, 명령 앞에 실행 사용자를 한 칸 더 적어요.

cron은 백그라운드 스케줄러예요. 사용자 crontab은 그 계정 권한으로 돌고, 시스템 파일은 적어 둔 사용자로 돌아요. 같은 명령도 어느 파일에 두느냐에 따라 환경과 권한이 달라져요.

- 사용자 작업은 `crontab -e`로 고치고 `crontab -l`로 다시 읽어요.
- 시스템 작업은 `/etc/crontab`과 `/etc/cron.d/`를 쓰고 사용자 필드를 빼지 않아요.
- 로그인 셸 환경을 물려받지 않으므로 `PATH`, `SHELL`, 작업 디렉터리를 적어요.
- 결과는 메일, 리다이렉트, 시스템 로그 중 하나로 남겨요.
- 저장은 보통 바로 반영되지만, 안 돌면 cron 서비스 상태와 로그를 봐요.

## cron 주기 설정 표

자주 쓰는 표현은 사용자 crontab 기준이에요. 시스템 cron 파일에 그대로 붙이면 사용자 필드가 빠져 문법 오류가 나요.

| 실행 목적 | crontab 예시 | 설명 |
| --- | --- | --- |
| 매시 정각 | `0 * * * *` | 분 필드만 고정하고 나머지는 모든 값을 뜻하는 별표로 둬요. |
| 일정 간격 | `*/10 * * * *` | 분 필드에 슬래시를 쓰면 그 간격마다 돌아요. |
| 매일 실행 | `0 4 * * *` | 시 필드에 원하는 시각을 적고 일, 월, 요일은 전체로 둬요. |
| 매주 실행 | `0 4 * * 1` | 요일 필드에 월요일을 뜻하는 값을 적어요. |
| 매월 실행 | `0 4 1 * *` | 일 필드에 날짜를 적고 월과 요일은 전체로 둬요. |

별표는 그 필드의 모든 값이에요. 쉼표는 목록, 하이픈은 범위, 슬래시는 간격이에요. `@daily`, `@weekly`, `@monthly`, `@reboot` 같은 별칭도 crontab 문서에 있지만, 팀이 쓰는 cron 구현이 이를 받는지 먼저 봐요.

필드 사이는 공백으로 나누고, 명령에는 스크립트 경로와 인자를 적어요. 주기만 맞고 환경이 비어 있으면 등록은 돼도 실행은 실패해요.

## 단계별 설정 방법

편집 전에 현재 작업과 실행 계정을 읽고, 절대 경로와 로그 리다이렉트를 같이 적어요. 저장 뒤에는 목록, 서비스 상태, 로그 순서로 봐요.

### 현재 작업과 권한 확인

`crontab -l`로 현재 사용자 작업을 읽어요. `whoami`와 `id`로 실행 계정을 보고, 시스템 작업이면 `sudo`가 필요한지 판단해요. 서비스 계정으로 돌려야 하는 일은 그 계정의 crontab에 두는 편이 권한 범위를 줄여요.

### crontab 편집과 주기 작성

`crontab -e`가 편집기를 열어요. 한 줄에 필드와 명령을 잇고, 설명은 `#`으로 시작해요. `0 4 * * * /usr/bin/bash /opt/app/scripts/backup.sh >> /var/log/app/backup.log 2>&1`처럼 절대 경로와 로그를 같이 적으면 실행 여부를 추적하기 쉬워요.

저장하고 편집기를 닫아요. 문법이 어긋나면 저장 단계에서 경고가 나오니 메시지를 읽어요. 등록 뒤에는 `crontab -l`로 의도한 줄이 들어갔는지 다시 봐요.

### 환경 변수와 작업 디렉터리 정리

cron은 로그인 셸의 환경을 받지 않아요. crontab 위에 `PATH=/usr/local/bin:/usr/bin:/bin`과 `SHELL=/bin/bash`를 적고, 필요하면 `MAILTO`로 결과를 받을 주소를 지정해요. 스크립트 안에서는 `cd /opt/app`처럼 작업 디렉터리를 직접 옮기고, 비밀 값은 권한이 좁은 환경 파일에서 읽어요.

### 로그와 종료 코드 확인

표준 출력과 표준 에러를 파일이나 로그 수집기로 보내면 조용한 실패를 줄일 수 있어요. 스크립트 끝에 종료 코드를 로그로 남기거나, 실패할 때 알림을 보내는 래퍼를 둬요. 등록 내용과 로그의 실행 시각이 맞는지 같이 봐요.

### 서비스 상태와 반영 확인

저장은 보통 cron이 감지하지만, 안 돌면 서비스 상태를 봐요. 배포판에 따라 이름이 `cron` 또는 `crond`라서 `systemctl status cron`과 `systemctl status crond` 중 있는 쪽을 써요. 컨테이너나 최소 이미지에는 cron이 없을 수 있으니 기반 이미지부터 봐요.

## 상황별 선택

단순한 정기 작업은 cron이 예측하기 쉬워요. 순서, 의존성, 재시도, 로그 통합이 중요해지면 스크립트와 운영 도구를 같이 설계해야 해요.

- **단순 백업·정리**: 절대 경로와 로그 리다이렉트를 한 줄에 적어요.
- **배포 자동화**: 배포 스크립트를 호출하되 `flock`으로 겹침을 막고, 실패 알림과 롤백 절차를 둬요.
- **여러 서버 운영**: 서버마다 손으로 고치기보다 구성 관리로 같은 작업을 배포해요.
- **복잡한 의존성**: systemd timer나 배포 도구의 스케줄을 검토해요. [systemd.timer 공식 문서](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html)에서 타이머 단위 동작을 볼 수 있어요.

배포 작업은 스크립트를 애플리케이션과 함께 버전 관리하고, 실행 계정과 로그 경로를 문서에 남겨요. cron은 시점만 담당하므로 성공 여부와 롤백은 별도 절차로 검증해요.

## 주의할 점

- **시간대**: cron은 서버 시스템 시간대를 기준으로 돌아요. 앱이 다른 시간대를 기대하면 시각이 어긋나므로 `timedatectl`로 서버 시간대를 봐요.
- **일 필드와 요일 필드**: Vixie cron 계열에서는 두 필드가 모두 제한되면 둘 중 하나만 맞아도 실행돼요. 날짜와 요일을 동시에 만족해야 하면 스크립트 안에서 조건을 검사해요.
- **퍼센트 기호**: crontab에서 `%`는 특별한 의미라서, 명령에 넣어야 하면 역슬래시로 이스케이프해요.
- **중복 실행**: 이전 작업이 끝나기 전에 다음 주기가 올 수 있어요. 잠금 파일이나 실행 시간 제한으로 겹침을 막아요.
- **권한과 비밀 값**: crontab에 비밀 값을 직접 적지 말고, 권한이 좁은 환경 파일이나 비밀 관리 도구를 써요.
- **삭제 명령**: `crontab -r`은 현재 사용자의 작업을 모두 지우므로 백업 없이 쓰지 않아요.
- **로그 비대화**: 리다이렉트한 로그가 커지지 않게 logrotate 같은 도구를 같이 둬요.

실행 셸과 대화형 셸의 차이를 전제로, 스크립트가 필요한 환경을 스스로 잡게 만들어요. 운영 서버에 처음 넣을 때는 알림을 켜 두고 로그를 본 뒤에 범위를 넓혀요.

## 자주 묻는 질문

### cron이 실행되지 않을 때 무엇을 먼저 확인해야 하나요?

`crontab -l`로 등록 여부를 보고, `systemctl status cron` 또는 `systemctl status crond`로 서비스 상태를 봐요. 그다음 명령 경로가 절대 경로인지, 실행 권한이 있는지 봐요. 배포판 로그나 `journalctl -u cron`의 오류 메시지로 원인을 좁혀요.

### 일 필드와 요일 필드를 함께 제한하면 어떻게 동작하나요?

많이 쓰는 Vixie cron 계열에서는 두 필드가 모두 제한되면 둘 중 하나만 맞아도 실행돼요. 특정 날짜이면서 특정 요일일 때만 돌리려면 필드를 동시에 좁히지 말고 스크립트 안에서 날짜를 검사해요. 구현마다 다를 수 있으니 쓰는 cron 문서를 기준으로 해요.

### 배포 자동화에 cron을 사용해도 괜찮나요?

가능하지만 겹침과 실패 복구를 같이 설계해야 해요. `flock`으로 동시 실행을 막고, 배포 로그와 실패 알림을 남기며, 이전 버전으로 되돌리는 절차를 준비해요. 의존성과 순서가 복잡하면 systemd timer나 배포 도구 스케줄이 더 맞아요.

### cron에서 환경 변수가 적용되지 않는 이유는 무엇인가요?

cron은 로그인 셸 환경을 받지 않고 제한된 환경에서 명령을 실행해요. `PATH`, `SHELL`, 앱 환경 변수를 crontab 위나 스크립트 안에 적어야 해요. 비밀 값은 crontab에 직접 적기보다 권한이 좁은 환경 파일을 읽게 해요.
