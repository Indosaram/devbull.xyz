linux timeout 명령의 종료 코드는 시간 초과인지, timeout 자신이 실패했는지, 감싼 명령이 스스로 끝난 것인지를 나눠요. 상태 유지 옵션이 없으면 시간 초과는 매뉴얼에 적힌 전용 코드로 돌아와요. 스크립트에서 그 코드를 명령 실패와 같은 분기로 두면 재시도가 잘못된 곳으로 가요. 아래는 코드별 의미와 확인 순서예요. 숫자는 설치한 coreutils 매뉴얼이 기준이에요.

![linux timeout command return code: 124·137·143 구분 소제목 카드. 한눈에 보기, 종료 코드 비교 표, 단계별로 확인하는 방법, 상황별 선택](/static/images/linux-timeout-command-return-code/diagram.webp)

## 한눈에 보기

timeout은 시간 안에 끝난 명령의 종료 상태를 그대로 전달하거나, 시간을 넘기면 신호를 보내고 별도 상태로 끝나요. 명령을 못 찾거나 실행할 수 없으면 timeout이 그 실패를 대신 알려요. 강제 종료 신호의 상태는 상태 유지 옵션이 있을 때와 없을 때가 달라요. 표의 코드를 스크립트 분기에 그대로 쓰기 전에 로컬 매뉴얼과 맞추세요.

## 종료 코드 비교 표

표는 정상, 시간 초과, timeout 자체 실패, 실행 불가, 명령 없음, 강제 종료 신호를 나눈 거예요. 같은 숫자라도 상태 유지 옵션이 있으면 명령이 받은 신호의 상태로 보일 수 있어요. 그 외 값은 명령이 스스로 반환한 것으로 보고 명령별 규칙을 따라요.

| 종료 코드 | 의미 | 주로 나오는 상황 | 스크립트에서의 판단 |
|---|---|---|---|
| 0 | 정상 종료 | 명령이 제한 시간 안에 스스로 끝남 | 성공으로 처리 |
| 124 | 시간 초과 | `--preserve-status` 없이 제한 시간을 넘김 | 재시도 또는 알림 대상 |
| 125 | timeout 자체 실패 | 잘못된 옵션, 실행 환경 문제 | 스크립트 버그로 보고 수정 |
| 126 | 실행할 수 없음 | 파일은 있으나 권한이나 실행 형식에 문제가 있음 | 배포 산출물 점검 |
| 127 | 명령을 찾을 수 없음 | PATH에 없거나 이름 오타 | 실행 환경·경로 점검 |
| 137 | KILL 시그널 | `--preserve-status`와 KILL 조합, 또는 `timeout` 자체가 KILL을 받음 | 강제 종료 흔적으로 기록 |
| 143 | TERM 시그널 | `--preserve-status` 상태에서 TERM으로 정리됨 | 정상적인 중단 절차로 기록 |
| 그 외 | 명령의 원래 상태 | 명령이 스스로 반환한 코드 | 명령별 규칙에 따라 처리 |

## 단계별로 확인하는 방법

감쌀 명령을 시간 제한 없이 한 번 실행해 자체 종료 코드를 알아 둬요. timeout으로 감싼 뒤 종료 상태를 찍어요. 시간 초과 전용 코드면 재시도나 알림으로 보내고, timeout 자체 실패면 옵션과 환경을 고쳐요. 명령 없음과 실행 불가는 배포 산출물과 PATH를 봐요. 상태 유지 옵션을 켰다면 신호로 죽은 상태와 시간 초과를 다시 구분해요.

```bash
timeout 10s sleep 300
echo $?
# 124
```

```bash
timeout --preserve-status 10s sleep 300
echo $?
# 143 (TERM으로 정리된 경우)
```

```bash
timeout --signal=TERM --kill-after=5s 30s ./deploy.sh
echo $?
```

```bash
timeout --signal=TERM --kill-after=5s 30s ./deploy.sh
status=$?

case "$status" in
  0)   echo "정상 종료" ;;
  124) echo "제한 시간 초과로 중단" ;;
  125) echo "timeout 실행 자체 실패" ;;
  126) echo "명령을 실행할 수 없음" ;;
  127) echo "명령을 찾을 수 없음" ;;
  137) echo "KILL 시그널로 종료" ;;
  143) echo "TERM 시그널로 종료" ;;
  *)   echo "명령이 반환한 실패 코드: $status" ;;
esac
```

## 상황별 선택

배포 스크립트는 시간 초과와 명령 실패를 다른 분기로 로그에 남겨요. 정리 시간이 필요하면 첫 신호 뒤 강제 종료를 예약하고, 그때의 코드가 표의 어느 줄인지 매뉴얼로 확인해요. CI는 무한 대기 방지용으로 쓰고, 실패 로그를 아티팩트로 남기세요. 애플리케이션 안 시간 제한과 바깥 timeout은 의미가 다르니 둘 다 쓸 거면 어느 쪽이 먼저인지를 적어요.

## 주의할 점

셸 내장은 timeout이 직접 실행하지 못해요. 파이프는 마지막 명령의 상태만 보일 수 있어서, 파이프 전체에 제한을 걸려면 묶어야 해요. 접미사 없는 시간은 초로 읽혀요. 숫자를 스크립트에 적을 때는 그 시스템의 timeout 매뉴얼과 같은지 확인해요. 자식이 손자를 남기면 종료 코드는 나와도 자원이 남아요.

```bash
timeout 30s sh -c 'dump-db | gzip > backup.gz'
```

## 자주 묻는 질문

시간 초과 코드, 강제 종료 코드, 스크립트 분기, 명령 없음, 접미사가 반복돼요.

### timeout이 124를 반환하는 이유는 무엇인가요?

상태 유지 옵션 없이 제한 시간을 넘기면, GNU timeout은 시간 초과를 그 전용 상태로 알려요. 명령이 스스로 같은 숫자를 반환할 수 있으니, 그 명령의 정상 코드와 겹치는지 먼저 봐요. 정확한 약속은 설치본 매뉴얼이 기준이에요.

### 137과 143은 각각 무엇을 뜻하나요?

보통 프로세스가 KILL 또는 TERM으로 끝났을 때의 상태예요. timeout에서는 상태 유지와 강제 종료 조합일 때 이 값이 보여요. 누가 신호를 보냈는지는 그 실행의 옵션과 로그로 나눠요.

### 스크립트에서 시간 초과와 명령 실패를 구분하려면 어떻게 하나요?

종료 상태를 케이스별로 나눠 시간 초과, timeout 자체 실패, 명령 없음을 다른 로그로 남겨요. 명령의 자체 실패는 그 명령의 규칙으로 처리해요. 모두 같은 재시도에 넣지 마세요.

### 127이 나오면 무엇을 확인해야 하나요?

명령을 못 찾은 상태예요. PATH, 작업 디렉터리, 이름 오타, 배포 시 빠진 파일을 봐요. timeout 문법 오류와는 다른 코드예요.

### 시간 지정 값에 접미사를 붙이지 않으면 어떻게 되나요?

초로 해석돼요. 분이나 시간을 의도했다면 접미사를 붙여야 해요. 빈 값이나 잘못된 단위는 timeout 자체 실패로 갈 수 있어요.
