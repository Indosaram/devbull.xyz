koyeb free tier는 소규모 백엔드 서비스를 비용 부담 없이 배포하고, 빌드부터 런타임까지 이어지는 배포 흐름을 미리 검증하는 용도에 잘 맞아요. 다만 무료 등급은 인스턴스 유형과 리전, 월 단위 사용량에 제한이 걸리기 때문에 실제 트래픽을 받는 운영 서비스보다는 검증 환경이나 개인 프로젝트에 두는 편이 안전해요. 정확한 한도와 제공 범위는 요금 페이지에서 직접 확인하는 습관이 필요해요.

## 한눈에 보기

koyeb free tier를 이해할 때 핵심은 "무료로 쓸 수 있는 범위"와 "무료에서는 제공되지 않는 범위"를 나눠서 보는 것이에요. 무료 등급은 계정을 만들고 저장소를 연결해 서비스를 배포하는 기본 흐름을 그대로 경험할 수 있게 해줘요. 반면 인스턴스 크기, 선택 가능한 리전, 동시에 돌릴 수 있는 서비스 수, 월 단위 사용량에는 상한이 있어요.

- 배포 방식은 Git 저장소 연동과 컨테이너 이미지 기반 배포를 모두 다룰 수 있어요.
- 무료 등급은 소규모 인스턴스 유형을 중심으로 제공되며, 더 큰 인스턴스는 유료 등급에서 선택하게 돼요.
- 트래픽이 없는 시간대에 서비스를 잠자기 상태로 전환하는 스케일 투 제로 동작을 이해해야 해요.
- 영구 볼륨이나 관리형 데이터베이스처럼 상태를 보관하는 리소스는 무료 등급에서 제한되거나 별도 구성이 필요해요.
- 정확한 수치와 정책은 시점에 따라 바뀔 수 있으므로 요금 페이지를 기준으로 판단해야 해요.

## 무료 등급과 유료 등급 비교

| 항목 | 무료 등급 | 유료 등급 |
| --- | --- | --- |
| 인스턴스 유형 | 소규모 유형 중심으로 제한 | 더 큰 유형까지 선택 가능 |
| 선택 가능한 리전 | 일부 리전으로 제한 | 문서에 안내된 리전 전반 |
| 동시 운영 서비스 | 소수로 제한 | 플랜에 따라 확장 |
| 스케일 투 제로 | 동작 대상이며 콜드 스타트 발생 | 유지 옵션과 조합 가능 |
| 영구 볼륨 | 제한적이거나 미제공 | 사용 가능 |
| 관리형 데이터베이스 | 별도 확인 필요 | 요금 페이지 기준 제공 |
| 사용량 초과 시 | 서비스 중단 또는 제한 | 추가 과금 또는 상향 |
| 지원 채널 | 커뮤니티 중심 | 플랜별 지원 범위 |

표에서 가장 중요한 줄은 "사용량 초과 시"와 "영구 볼륨"이에요. 무료 등급은 한도에 닿았을 때 과금이 아니라 중단이나 제한으로 이어지는 경우가 많아서, 장애 원인을 찾을 때 한도 초과를 먼저 의심해야 해요.

## 무료 등급으로 서비스 배포하기

무료 등급에서도 배포 절차 자체는 유료 등급과 크게 다르지 않아요. 아래 순서대로 진행하면 무료 범위 안에서 서비스를 띄울 수 있어요.

- 배포할 애플리케이션을 Git 저장소에 올리고, 빌드에 필요한 설정 파일을 저장소 루트에 둬요. Node.js나 Python처럼 런타임이 명확한 경우에는 빌드팩이 자동으로 감지하는 경우가 많아요.
- Koyeb 계정을 만든 뒤 Git 제공자와 연동해요. 저장소 접근 권한은 필요한 범위만 주는 편이 안전해요.
- 새 서비스를 만들고 저장소와 브랜치를 선택해요. 배포 트리거는 특정 브랜치에 푸시가 들어올 때로 잡아두면 이후 자동 배포가 편해져요.
- 빌드 방식은 빌드팩과 Dockerfile 중에서 고를 수 있어요. 이미지 크기를 줄이고 싶다면 멀티 스테이지 Dockerfile을 권해요.
- 서비스가 수신할 포트를 애플리케이션 설정과 맞춰요. Koyeb가 요구하는 기본 포트와 애플리케이션이 실제로 여는 포트가 어긋나면 헬스체크에서 실패해요.
- 환경 변수와 시크릿을 등록해요. 데이터베이스 접속 정보나 API 토큰은 저장소에 커밋하지 말고 시크릿으로 넣어야 해요.
- 인스턴스 유형과 리전을 선택해요. 무료 등급에서는 선택지가 제한되므로, 지연에 민감한 사용자층이 있다면 제공되는 리전을 먼저 확인해야 해요.
- 배포를 실행하고 빌드 로그와 런타임 로그를 순서대로 확인해요. 첫 배포에서 실패하는 지점은 대부분 의존성 설치와 포트 설정이에요.
- 정상 기동을 확인한 뒤 기본 제공 도메인으로 접속해 동작을 검증하고, 필요하면 커스텀 도메인을 연결해요.

배포가 끝난 뒤에는 반드시 스케일 투 제로 동작을 확인해요. 일정 시간 요청이 없으면 서비스가 잠자기 상태로 들어가고, 다음 요청에서 기동 시간이 더해지면서 첫 응답이 느려질 수 있어요. 이 동작을 모르면 "가끔 느리다"는 현상을 애플리케이션 문제로 오해하기 쉬워요.

## 상황별 선택 기준

무료 등급을 계속 쓸지, 유료로 올릴지는 워크로드의 성격으로 갈리는 경우가 많아요.

개인 토이 프로젝트나 학습용 API라면 무료 등급으로 충분해요. 요청이 뜸한 시간이 길어도 문제가 되지 않고, 잠자기 상태에서 깨어나는 지연도 감수할 수 있어요.

포트폴리오 데모나 코드 리뷰용 미리보기 환경도 무료 등급과 잘 맞아요. 다만 데모를 보는 사람이 곧바로 접속하는 상황에서는 첫 응답이 느릴 수 있으니, 발표 전에 한 번 요청을 보내 서비스를 깨워두는 편이 좋아요.

스테이징 환경이라면 무료 등급을 쓸 수 있지만, 운영과 동일한 인스턴스 유형을 검증하려는 목적이라면 유료 등급이 필요해요. 성능 특성이 다른 인스턴스에서 통과한 테스트는 운영 환경에서 다시 깨질 수 있어요.

실제 사용자가 붙는 API라면 유료 등급을 검토해야 해요. 무료 등급은 한도 초과 시 중단으로 이어질 수 있어서, 장애 대응 비용이 절감액보다 커지는 상황이 생겨요.

상태를 저장해야 하는 서비스도 판단이 갈려요. 영구 볼륨이 제한된다면 파일 업로드나 세션 저장은 외부 오브젝트 스토리지나 외부 데이터베이스로 분리하는 구성이 안전해요. 이렇게 분리해두면 나중에 플랫폼을 옮길 때도 이전 비용이 줄어들어요.

배치 작업이나 크론 형태의 워크로드는 무료 등급의 실행 시간 한도와 잘 맞는지 먼저 따져봐야 해요. 주기적으로 오래 도는 작업은 한도에 빨리 닿을 수 있어요.

## 주의할 점

무료 등급을 운영에 가깝게 쓸 때 자주 부딪히는 지점을 정리했어요.

첫째, 콜드 스타트를 사용자 경험 설계에 반영해야 해요. 잠자기 상태에서 깨어나는 시간을 감안해 타임아웃을 넉넉히 잡고, 첫 요청이 느릴 수 있다는 안내를 두는 편이 좋아요.

둘째, 월 단위 한도를 모니터링해야 해요. 대역폭이나 빌드 사용량이 한도에 가까워지면 배포가 실패하거나 서비스가 제한될 수 있어요. 대시보드에서 사용량을 주기적으로 확인하는 습관이 필요해요.

셋째, 리전 제한을 지연 요구사항과 함께 봐야 해요. 무료 등급에서 선택할 수 있는 리전이 사용자 위치와 멀면 네트워크 왕복 시간이 늘어나요.

넷째, 시크릿 관리가 소홀해지기 쉬워요. 무료 등급이라고 해서 환경 변수 취급이 달라지지는 않으니, 토큰은 저장소가 아니라 플랫폼 시크릿에 넣고 주기적으로 교체해야 해요.

다섯째, 무료 등급 정책은 바뀔 수 있어요. 제공 범위가 조정되면 갑자기 배포가 막히거나 서비스가 중단될 수 있으므로, 요금 페이지와 문서의 변경 사항을 가끔 확인하는 편이 안전해요.

여섯째, 무료 등급만으로 백업 체계를 갖추기는 어려워요. 데이터는 외부 저장소에 두고, 플랫폼은 실행 환경으로만 쓰는 구조가 장애에 강해요.

## 자주 묻는 질문

### koyeb free tier로 상용 서비스를 운영해도 되나요?

기술적으로 배포는 가능하지만 권장하지는 않아요. 무료 등급은 사용량 한도와 스케일 투 제로 동작이 있어서 트래픽이 몰리는 시점에 응답 지연이나 중단이 생길 수 있어요. 실제 사용자가 붙는 서비스라면 유료 등급으로 올리거나 다른 플랫폼과 비교해 결정하는 편이 안전해요.

### 무료 등급에서 서비스가 잠자기 상태로 바뀌는 이유는 무엇인가요?

요청이 없는 시간에 자원을 회수해 무료 사용량을 유지하기 위한 동작이에요. 다음 요청이 들어오면 서비스를 다시 기동하면서 첫 응답에 시간이 더해져요. 이 지연이 문제라면 최소 실행 인스턴스를 유지하는 유료 옵션을 검토해야 해요.

### 무료 등급에서 데이터베이스나 영구 볼륨을 쓸 수 있나요?

제공 범위가 제한적이거나 별도 구성이 필요한 경우가 많아요. 상태를 보관해야 하는 서비스라면 외부 관리형 데이터베이스나 오브젝트 스토리지를 함께 쓰는 구조를 권해요. 정확한 제공 여부는 요금 페이지와 문서에서 확인해야 해요.

### 무료 등급의 정확한 한도는 어디서 확인하나요?

공식 요금 페이지와 문서의 무료 등급 안내 항목에서 확인할 수 있어요. 한도는 인스턴스 유형, 리전, 월 사용량 기준으로 나뉘어 안내되며 시점에 따라 조정될 수 있어요. 배포 전에 한 번, 운영 중에 주기적으로 확인하는 편이 좋아요.

### 무료 등급만으로 배포 자동화를 구성할 수 있나요?

저장소 연동과 브랜치 기반 자동 배포는 무료 등급에서도 기본 흐름으로 다룰 수 있어요. 다만 빌드 사용량이 한도에 걸리면 자동 배포가 실패할 수 있으므로, 빌드 캐시를 활용하고 이미지 크기를 줄이는 최적화가 함께 필요해요.
