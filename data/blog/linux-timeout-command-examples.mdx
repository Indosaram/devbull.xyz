오래 걸리는 명령을 그냥 두면 배포 스크립트와 점검 작업이 끝나지 않아요. GNU coreutils의 timeout은 그 명령에 시간 상한을 걸고, 시간이 지나면 신호를 보내요. 기본은 종료를 요청하는 신호이고, 정리가 더 필요하면 강제 종료 시점을 따로 둘 수 있어요. 아래는 문법, 자주 쓰는 옵션, 스크립트에서 상태를 나누는 방법이에요.

## 한눈에 보기

timeout은 지정한 시간 안에 끝나지 않은 명령에 신호를 보내는 도구예요. 외부 호출, 로그 압축, 끝나지 않을 수 있는 조회를 감쌀 때 써요. 기본 형태는 timeout 뒤에 시간과 명령을 두는 거예요. 시간 값에 접미사를 생략하면 초로 읽히고, 신호는 옵션으로 바꿀 수 있어요. 첫 신호 뒤에도 프로세스가 남으면 강제 종료용 대기 시간을 따로 둬요. 시간 초과와 명령 자신의 실패를 구분하려면 종료 상태를 스크립트에서 나눠 봐요.

## 기본 문법과 시간 지정 방식

문법은 timeout, 옵션, 시간, 명령, 인자 순서예요. 시간은 명령을 얼마나 기다릴지이고, 그 뒤가 실제 실행 파일이에요. 접미사로 초, 분, 시, 일을 구분할 수 있고, 접미사가 없으면 초예요. 소수 형식도 매뉴얼에 있지만, 운영 스크립트에서는 의도가 분명한 정수 표기가 읽기 좋아요. 파이프 전체에 상한을 걸려면 셸이 파이프를 한 명령으로 받게 묶어야 해요.

## 자주 쓰는 옵션 비교

표는 신호를 바꾸는 옵션, 강제 종료까지의 추가 대기, 명령의 원래 상태를 유지하는 옵션을 나눠 둔 거예요. 기본 신호만으로 자식이 정리를 무시하면 프로세스가 남아요. 그때 추가 대기가 있는 강제 종료 옵션이 필요해요. 명령이 스스로 돌려준 상태를 배포 스크립트의 성공 기준으로 쓰고 싶다면 상태 유지 옵션을 검토하되, 시간 초과와 명령 실패가 섞이지 않는지 먼저 확인해요.

| 옵션 | 역할 | 예시 |
| --- | --- | --- |
| `-s SIGNAL` | 시간 초과 시 보낼 신호를 지정해요 | `timeout -s TERM DURATION COMMAND` |
| `--signal=SIGNAL` | 신호 지정을 긴 옵션 형태로 써요 | `timeout --signal=TERM DURATION COMMAND` |
| `-k GRACE` | 첫 신호 후 추가 대기하고, 그 뒤 KILL을 보내요 | `timeout -k GRACE DURATION COMMAND` |
| `--preserve-status` | 시간 초과여도 명령의 종료 상태를 유지해요 | `timeout --preserve-status DURATION COMMAND` |
| `--foreground` | 터미널 제어가 필요한 명령을 위해 포그라운드에서 실행해요 | `timeout --foreground DURATION COMMAND` |
| `--verbose` | timeout 자체의 진단 메시지를 stderr로 보내요 | `timeout --verbose DURATION COMMAND` |

## 단계별 사용 방법

먼저 감쌀 명령이 대화형인지, 자식 프로세스를 더 만드는지 봐요. 그다음 시간 상한을 업무가 끝나야 하는 기한보다 짧게 두고, 기본 실행으로 신호가 전달되는지 확인해요. 정리가 필요한 서버 프로세스라면 강제 종료 시점을 한 단계 뒤에 둬요. 마지막으로 종료 상태를 분기해 시간 초과, 명령 없음, 명령 자신의 실패를 로그에 다르게 남겨요. 예시는 매뉴얼의 형식만 따르고, 운영 값은 서비스 특성에 맞게 고르세요.

## 상황별 선택 기준

한 번 돌고 끝나는 조회나 압축은 기본 신호만으로 충분한 경우가 많아요. 요청을 받아 자식을 띄우는 작업은 프로세스 그룹 전체에 신호를 보낼지 매뉴얼의 해당 옵션을 봐요. CI에서 무한 대기만 막으면 되면 짧은 상한과 실패 시 로그 수집이 맞아요. 애플리케이션 안에 이미 시간 제한이 있다면 timeout은 바깥 안전망으로만 두고, 안쪽 제한과 바깥 상한이 서로 다른 의미라는 점을 적어 두세요.

## 주의할 점

timeout이 죽인 것처럼 보여도, 손자가 남으면 포트나 잠금이 계속 잡혀 있어요. 셸 내장 명령은 실행 파일이 아니라서 timeout이 직접 못 감싸요. 시간 문자열을 비우거나 옵션 순서를 바꾸면 timeout 자신이 실패해요. 이 실패와 시간 초과를 같은 분기로 처리하면 스크립트 버그를 재시도로 가려요. 권한 없는 경로의 명령을 감싸면 실행 불가 상태가 나오고, 이름 오타면 명령을 찾을 수 없다는 상태가 나와요.

## 자주 묻는 질문

신호와 종료 상태를 구분하는 질문이 가장 많아요.

### timeout은 기본적으로 어떤 신호를 보내나요?

기본은 TERM이에요. 대상이 이 신호를 무시하면 프로세스가 남으니, 신호 옵션으로 바꾸거나 뒤이어 강제 종료를 예약해요. 매뉴얼의 신호 이름 표기를 그대로 쓰는 편이 셸마다 해석이 갈리지 않아요.

### `-k`는 언제 쓰나요?

첫 신호 뒤에 정리 시간을 더 주고, 그래도 안 끝나면 KILL로 거둘 때 써요. 데이터 파일을 닫아야 하는 명령에 바로 KILL만 보내면 파일이 중간 상태로 남을 수 있어요. 그래서 요청 신호와 강제 종료 시점을 나누는 옵션이에요.

### 시간 초과 종료 코드는 어떻게 확인하나요?

상태 유지 옵션이 없으면 시간 초과는 매뉴얼에 적힌 전용 종료 상태로 돌아와요. 스크립트에서는 그 상태, 명령 없음, 실행 불가를 서로 다른 분기로 로그에 남겨요. 정확한 숫자는 설치한 coreutils의 timeout 매뉴얼을 기준으로 봐요.
