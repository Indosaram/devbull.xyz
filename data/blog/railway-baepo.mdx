Railway 배포는 프로젝트를 만들고 서비스를 연결한 뒤, Git 푸시나 CLI, Docker로 빌드와 실행을 맡기는 흐름이에요. 저장소가 없어도 CLI로 올릴 수 있지만, 반복 배포는 Git 연동이 추적이 쉬워요. 실패는 빌드 로그, 시작 로그, 헬스 체크 중 어디에 있는지로 나눠요. 아래는 준비부터 도메인과 롤백까지예요.

![railway 배포 기초: 처음 배포할 때 확인할 흐름 소제목 카드. 한눈에 보기, 배포 방식 비교, 단계별 배포 방법, 상황별 선택](/static/images/railway-baepo/diagram.webp)

## 한눈에 보기

서비스 하나가 배포 단위이고, 프로젝트는 그 서비스와 데이터베이스를 묶는 곳이에요. 빌드 명령과 시작 명령, 포트, 환경 변수가 맞아야 공개 주소가 살아 있어요. 배포 성공 표시와 프로세스가 요청을 받는 것은 달라요. 공식 퀵스타트와 배포 가이드의 화면 이름을 기준으로 따라가면 돼요.

## 배포 방식 비교

표는 GitHub 연동, CLI, 설정 파일을 코드로 두는 방식을 나눈 거예요. 팀 리뷰가 있으면 Git, 저장소 없이 시험하면 CLI, 설정을 저장소에 고정하면 코드형 설정이 맞아요. 방식을 섞으면 어느 설정이 우선인지 문서에서 확인해요.

| 항목 | GitHub 연동 | CLI 업로드 | Dockerfile 기반 |
| --- | --- | --- | --- |
| 시작 방식 | 저장소를 연결해 커밋 기준으로 배포 | 로컬 디렉터리를 Railway CLI로 업로드 | 저장소의 Dockerfile로 빌드 |
| 잘 맞는 상황 | 팀 협업과 지속적인 배포 | 빠른 실험이나 저장소 밖 배포 | 런타임과 시스템 패키지를 직접 제어 |
| 확인할 점 | 브랜치와 자동 배포 설정 | 업로드 범위와 제외 파일 | 이미지 빌드 시간과 캐시 |
| 공통 확인 | 시작 명령, 포트, 환경 변수 | 시작 명령, 포트, 환경 변수 | 시작 명령, 포트, 환경 변수 |

## 단계별 배포 방법

구조, 빌드, 시크릿, 도메인, 로그 순서로 보면 실패 위치가 줄어요.

### 프로젝트와 서비스 구조 정리

앱과 데이터베이스를 서비스로 나누고, 볼륨이 어디에 붙는지 적어요. 모노레포면 서비스 루트를 지정해요. 시험용 프로젝트와 운영 프로젝트를 섞지 않아요.

### 저장소 연결과 빌드 설정

브랜치와 빌드, 시작 명령을 로컬과 같게 둬요. 자동 배포 브랜치를 운영과 나누면 실험 커밋이 올라가지 않아요. 빌드 로그의 첫 오류가 의존성인지 명령 오타인지 봐요.

### 환경 변수와 시크릿 관리

비밀은 저장소가 아니라 서비스 변수로 넣어요. 환경마다 값 세트를 나눠요. 빠진 변수는 빌드가 아니라 시작 순간에 터지는 경우가 많아요.

### 도메인과 헬스 체크

기본 도메인으로 응답을 본 뒤 사용자 도메인을 연결해요. 헬스 경로는 인증 없이 가볍게 둬요. 앱은 주입된 포트를 들어야 해요.

### 배포 로그 확인과 롤백

빌드 로그와 런타임 로그를 구분해요. 문제가 있으면 이전 배포를 다시 활성화할지, 코드를 되돌려 재배포할지 정해요. 롤백 뒤에도 환경 변수가 새 값이면 증상이 남을 수 있어요.

## 상황별 선택

혼자 사이드 프로젝트면 Git 연동으로 시작해요. 일회성 산출물은 CLI예요. 런타임이 특이하면 Docker로 고정해요. 팀은 환경 분리와 청구 알림을 먼저 켜요.

## 주의할 점

서비스를 멈춰도 볼륨은 남을 수 있어요. 헬스 체크에 인증을 걸면 정상 앱도 실패로 보여요. 잘못된 프로젝트에 CLI를 연결하면 다른 서비스를 덮어요. 가격과 포함 범위는 공식 문서를 봐요.

## 자주 묻는 질문

저장소 필요 여부, 실패 위치, 변수, 도메인이 반복돼요.

### Railway 배포는 GitHub 저장소가 꼭 필요한가요?

아니에요. CLI나 Docker로 저장소 없이 올릴 수 있어요. 반복 배포와 리뷰가 필요하면 그때 저장소를 연결해요.

### 배포가 실패하면 어디부터 확인해야 하나요?

빌드 로그의 첫 오류, 시작 로그의 포트와 변수, 헬스 체크 순서로 봐요. 도메인은 프로세스가 살아 있는 뒤에 봐요.

### 환경 변수는 어디에 두나요?

서비스 설정의 변수 영역에 두고 저장소와 분리해요. 로컬용 파일은 배포 값을 대신하지 않아요. 환경이 여러 개면 세트도 나눠요.

### 배포 후 도메인은 어떻게 연결하나요?

네트워킹에서 기본 도메인을 확인한 뒤, 사용자 도메인은 안내된 DNS 레코드로 연결해요. 인증서 상태가 끝나기 전에 사용자를 안내하지 않아요.
