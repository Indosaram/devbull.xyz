버그에는 두 종류가 있다. 터지는 버그와, 조용히 아무 일도 안 하는 버그다.

터지는 버그는 싸다. 스택 트레이스가 어디서 났는지 알려주고, 대개 몇 분 안에 원인이 보인다.

조용한 버그는 다르다. 요청은 200으로 돌아오고, 로그는 비어 있고, 화면은 정상처럼 보인다. 그런데 데이터가 안 쌓인다. 이런 버그는 발견되는 순간보다 발견되지 않은 채로 흐른 시간이 더 큰 비용이다.

## 왜 조용해지는가

대부분 `catch` 블록에서 시작한다.

```
try {
  await save(order)
} catch (e) {
  console.log(e)
}
```

이 코드는 실패를 삼킨다. 호출자는 성공했다고 믿고 다음 단계로 간다. 실패는 로그 한 줄로 격하되고, 그 로그는 아무도 안 본다.

## 시끄럽게 만드는 세 가지

첫째, 삼키지 않는다. 복구할 수 없는 실패는 그대로 던진다. 복구할 수 있는 실패만 잡는다.

둘째, 결과를 확인한다. 쓰기 작업 뒤에는 반환값이나 영향받은 행 수를 검사한다. `update`가 0건을 갱신했는데 성공으로 처리하면 그게 조용한 실패다.

셋째, 기대값을 명시한다. 함수가 무엇을 보장하는지 계약으로 적고, 계약이 깨지면 즉시 실패하게 만든다.

## 계측

조용한 실패는 대개 지표로 먼저 보인다. 성공률, 처리 건수, 큐 길이 같은 숫자가 어제와 다르면 그게 신호다. 에러율만 보면 안 잡힌다 — 에러가 안 나기 때문이다.

가장 싼 보험은 "이 작업이 성공했다면 무엇이 참이어야 하는가"를 한 줄로 적어두는 것이다. 그 한 줄이 나중의 몇 시간을 아낀다.
