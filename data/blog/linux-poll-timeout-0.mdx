linux poll timeout 0은 이벤트를 기다리지 않고, 호출한 순간에 준비된 파일 디스크립터만 확인하고 바로 돌아오라는 뜻이에요. 음수는 이벤트가 올 때까지 기다리고, 양수는 그 만료까지만 기다려요. 0을 루프에서 계속 호출하면 대기 없이 돌면서 CPU를 쓸 수 있어요. 아래는 언제 0이 필요하고, 어떻게 고르는 기준이에요.

## 한눈에 보기

poll은 여러 파일 디스크립터가 읽기나 쓰기가 가능한지 묻는 시스템 호출이에요. 타임아웃 인자가 대기 시간을 정해요. 0은 논블로킹 확인이고, 준비가 없으면 즉시 반환해요. 이벤트를 기다리는 메인 루프의 기본값으로 0을 두면 대기 없이 바쁜 반복이 돼요.

## poll 타임아웃 비교 표

표는 음수, 0, 양수의 대기 방식을 나눈 거예요. 유휴 대기는 음수나 적절한 양수, 이미 쌓인 이벤트를 비우는 확인은 0, 타이머와 함께 쓰면 양수예요. 반환값 0은 시간 초과로 준비된 디스크립터가 없다는 뜻이고, 오류와는 달라요.

| 타임아웃 인자 | poll 동작 | 대표 사용 상황 |
| --- | --- | --- |
| 음수 | 이벤트가 올 때까지 기다려요 | 유휴 상태에서 이벤트를 기다리는 메인 루프 |
| 0 | 즉시 반환하고 현재 준비 상태만 확인해요 | 논블로킹 점검, 큐 소진 후 재확인, 종료 플래그 확인 |
| 양수 | 지정한 만료 조건까지만 기다려요 | 타이머와 이벤트를 함께 처리하는 루프 |

## linux poll timeout 0이 필요한 상황

다른 스레드가 넣어 둔 큐를 잠금 없이 한 번만 비울 때, 종료 플래그를 확인한 뒤 바로 다음 일로 돌아갈 때 써요. 소켓이 지금 읽을 수 있는지만 보고 없으면 다른 일을 해야 할 때도 맞아요. 대부분의 서버 루프는 0으로 도는 대신 이벤트가 올 때까지 기다리는 호출이 맞아요. 논블로킹 읽기와 같은 말은 아니에요. 디스크립터 플래그와 타임아웃은 따로예요.

## 단계별 확인 방법

관심 있는 디스크립터와 이벤트를 pollfd에 채워요. 타임아웃에 0을 넣고 호출한 뒤, 양수면 준비된 개수, 0이면 지금 준비된 것이 없음, 음수면 오류예요. 오류면 errno를 보고 인터럽트인지 잘못된 인자인지 나눠요. 준비된 디스크립터만 읽고, 다시 0으로 돌릴지는 큐가 남았는지로 결정해요.

## 상황별 선택 기준

메인 루프는 대기하는 타임아웃이 맞아요. 이미 깨어난 뒤 남은 이벤트를 한 번 더 훑을 때만 0을 써요. 주기적인 다른 일이 있으면 양수로 상한을 두고 그 일에 돌아가요. epoll을 쓰는 코드도 같은 의미로 타임아웃 0을 쓸 수 있지만, 관심 목록을 관리하는 방식은 달라요.

## 주의할 점

0 호출을 빈 루프에 두면 CPU를 계속 써요. 레벨 트리거에서 데이터를 덜 읽고 다시 poll하면 바로 또 깨어나요. 타임아웃 0과 논블로킹 소켓을 섞을 때는 둘 다 즉시 반환이라 오류 처리를 구분해요. 시그널로 끊긴 호출과 타임아웃 반환을 같은 분기로 두지 마세요.

## 자주 묻는 질문

논블로킹과의 차이, CPU, 반환 0, epoll과의 비교가 반복돼요.

### poll timeout 0은 논블로킹 읽기와 같은 뜻인가요?

아니에요. 타임아웃 0은 poll이 기다리지 않는다는 뜻이고, 논블로킹은 읽기나 쓰기 호출이 기다리지 않는다는 뜻이에요. 둘을 같이 쓸 수는 있지만 설정 위치가 달라요.

### timeout 0으로 계속 호출하면 CPU를 많이 쓰나요?

준비가 없어도 바로 돌아오므로, 그 호출만 반복하면 대기가 없어 CPU를 써요. 이벤트를 기다릴 때는 음수나 양수 타임아웃으로 잠재워요. 0은 이미 깨어난 뒤의 확인용으로 좁혀요.

### poll이 0을 반환하면 오류인가요?

아니에요. 타임아웃 안에 준비된 디스크립터가 없다는 뜻이에요. 타임아웃이 0이면 지금 준비가 없다는 뜻이에요. 오류는 음수 반환과 errno로 봐요.

### epoll_wait timeout 0과 같나요?

기다리지 않고 현재 준비만 본다는 점은 같아요. 관심 목록을 매번 넘기는지, 미리 등록하는지는 달라요. 엣지 트리거면 이벤트를 놓치지 않게 읽는 양이 더 중요해요.
