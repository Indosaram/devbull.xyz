## 한눈에 보기

무료 티어는 개인 프로젝트나 작은 API를 시험하기에 편한 출발점이에요. 다만 무료가 모든 네트워크 트래픽을 제한 없이 준다는 뜻은 아니에요. 대역폭은 서비스가 밖으로 응답을 보내는 과정에서 쌓이는 사용량으로 보면 돼요.

중요한 것은 제공량 숫자보다 계산 기준과 초과 뒤의 처리예요. 정책은 바뀔 수 있으니 예전 글의 수치를 그대로 쓰기보다 가격 페이지와 공식 문서를 기준으로 해요.

운영은 이 순서가 읽기 쉬워요.

- 무료 티어에 포함된 대역폭 범위를 문서에서 읽어요.
- 응답 종류와 호출이 얼마나 반복되는지 파악해요.
- 대시보드에서 사용량 위치를 미리 찾아 둬요.
- 캐시, 압축, 이미지 크기로 전송량을 줄여요.
- 트래픽이 커질 조짐이 있으면 유료 플랜이나 별도 전송 경로를 검토해요.

## 무료 티어 대역폭이 의미하는 것

대역폭은 네트워크로 오가는 데이터 양을 뜻해요. Koyeb에 올린 앱은 요청을 받고 HTML, JSON, 이미지, 파일을 돌려주는데, 밖으로 나가는 그 응답이 사용량 계산에 들어갈 수 있어요.

방문자 수와 전송량은 비례하지 않아요. 같은 사람이라도 본문이 큰 API를 부르면 전송량이 커지고, 정적 파일을 캐시하면 줄어들 수 있어요. 무료 범위를 오래 쓰려면 방문자만 보지 말고 응답 크기와 반복 요청을 같이 봐요.

포함 범위와 초과 처리 방식은 가격 페이지가 기준이에요. 배포 직전과 운영 중에 그 페이지를 다시 읽는 습관이 필요해요. 무료에서 유료로 넘어가는 조건은 문서마다 표현이 다를 수 있으니 가격 페이지와 사용량 문서를 같이 봐요.

## 공식 문서에서 확인할 항목

기능 소개보다 사용량과 요금에 붙는 항목을 먼저 봐요.

- 무료 티어에 포함되는 서비스 범위와 리소스 제한
- 대역폭이나 네트워크 사용량을 세는 기준
- 무료 범위를 넘었을 때의 청구 또는 제한
- 리전과 경로에 따라 달라지는 조건이 있는지
- 사용량을 보는 대시보드 위치
- 유료 플랜으로 바꾸면 달라지는 운영 옵션

“무료 티어 대역폭이 제한 없이 제공되는지”를 먼저 봐요. 제한이 있다면 어느 시점에 과금이 시작되는지, 알림을 받을 수 있는지가 중요해요. 문서 표현이 애매하면 가격 페이지의 조건과 지원 문서를 같이 읽어요.

가격 페이지는 제공량과 플랜 차이, 문서는 사용량 확인 방법과 제한을 나눠 보면 덜 헷갈려요.

## 요금·사용량 비교 표

아래는 운영할 때 비교할 기준이에요. 제공량과 가격 숫자는 공식 가격 페이지를 기준으로 해요.

| 대역폭 | 플랜에 포함된 사용량 범위 안에서 제공 | 사용량에 따른 청구와 플랜 조정이 가능 |
| 서비스 운영 | 제한된 리소스와 기능 범위 | 더 넓은 리소스와 운영 옵션 |
| 트래픽 급증 | 초과 위험을 직접 관리해야 함 | 예산, 알림, 플랜 조정으로 대응 |
| 모니터링 | 대시보드 사용량을 자주 봐야 함 | 청구서와 사용량 추이를 같이 봄 |

| 비용 예측 | 포함 범위 안에서는 변동이 적음 | 사용량에 따라 비용이 움직임 |

무료 티어는 “비용이 없는 환경”보다 “정해진 범위 안에서 비용을 통제하는 환경”에 가까워요. 응답이 작은 동안은 충분할 수 있지만, 큰 파일을 자주 내려주거나 외부 호출이 많으면 사용량이 빨리 늘어요.

## 배포 전 확인 단계

배포 전에 대역폭과 연결된 항목을 적어 두면 운영 중에 덜 당황해요.

1. 공식 가격 페이지에서 무료 티어 대역폭 항목과 초과 정책을 읽어요.
2. 밖으로 내보내는 응답이 HTML, JSON, 이미지, 파일 중 무엇인지 나눠요.
3. 대시보드에서 사용량을 보는 위치를 미리 찾아 둬요.
4. 정적 파일과 API 응답을 나누고, 캐시할 응답에는 캐시 헤더를 붙여요.
5. 파일 다운로드가 많으면 오브젝트 스토리지나 별도 전송 경로를 검토해요.
6. 사용량이 늘 때 알림을 받을 수 있는지, 유료로 바꿀 기준이 있는지 정해 둬요.

가장 큰 응답이 무엇인지부터 봐요. 목록 API가 한 번에 많은 필드를 돌려주거나 이미지 원본을 그대로 내려주면 사용량이 빨리 늘어요. 응답이 작고 캐시가 되면 같은 방문에서도 전송량을 줄일 수 있어요.

## 대역폭을 줄이는 운영 방법

응답을 작게 만드는 것이 기본이에요. 목록은 필요한 필드만 주고 페이지를 나눠 한 번의 본문을 줄여요.

정적 자산은 캐시와 압축을 같이 써요. 자주 안 바뀌는 CSS, JavaScript, 이미지는 캐시 기간을 길게 잡고, 텍스트 응답은 압축해요. 캐시를 잘못 두면 배포 뒤에도 이전 파일이 보이니, 파일 이름에 해시를 붙이거나 배포 때 무효화하는 방법을 같이 정해요.

이미지와 동영상은 특히 커요. 원본을 그대로 내려주지 말고 썸네일을 따로 두고, 필요하면 외부 스토리지로 파일을 빼요. 로그와 모니터링을 밖으로 많이 보내는 구조도 네트워크 사용량에 들어가니 주기와 크기를 같이 봐요.

불필요한 요청도 줄여요. 헬스 체크가 너무 잦거나 프론트가 같은 API를 반복 호출하면 캐시나 요청 병합으로 줄일 수 있어요. 배포 뒤에도 응답 크기와 호출 패턴을 주기적으로 보는 편이 좋아요.

## 상황별 선택 기준

포트폴리오나 문서 사이트처럼 트래픽이 작고 정적 페이지가 중심이면 무료 티어로 시작해도 돼요. 응답이 작고 캐시가 되면 포함 범위 안에서 운영하기가 상대적으로 수월해요.

소규모 API와 시험 서버도 잘 맞는 용도예요. 외부 사용자가 늘 가능성이 있으면 대시보드를 자주 보고, 특정 API 응답이 커지지 않게 제한을 둬요.

이미지와 파일 다운로드가 많은 서비스는 무료 티어만으로 버티기 어려울 수 있어요. 파일은 오브젝트 스토리지에 두고, 앱은 인증과 메타데이터만 처리하게 나누는 편이 안전해요.

트래픽 변동이 큰 운영 서비스는 무료 티어에 기대기보다 유료 플랜이나 다른 인프라를 같이 검토해요. 무료 티어는 비용 실험에는 유용하지만, 예측이 어려운 트래픽의 운영 환경으로는 부족할 수 있어요.

## 주의할 점

가장 흔한 실수는 “무료니까 제한이 없다”고 보는 것이에요. 포함 범위가 있고, 넘으면 청구나 제한이 생길 수 있으니 공식 정책을 기준으로 해요.

플랫폼마다 계산 기준이 달라요. 밖으로 나가는 트래픽만 보는 곳도 있고, 다른 통신을 포함하는 곳도 있어요. Koyeb 문서의 용어를 기준으로 읽고, 커뮤니티 경험만으로 정책을 단정하지 않아요.

대역폭이 남아도 메모리나 CPU 제한 때문에 느려질 수 있어요. 네트워크만 따로 보지 말고 전체 리소스를 같이 봐요.

가격과 정책은 바뀌어요. 배포 전에 읽은 내용이 나중에 그대로라고 가정하지 말고, 운영 중에도 공식 페이지를 다시 봐요. 유료 전환을 생각하면 청구 기준과 지원 범위를 같이 비교해요.

## 자주 묻는 질문

### Koyeb 무료 티어에 대역폭 한도가 있나요?

네, 무료 티어는 플랜이 정한 사용량 범위 안에서 대역폭을 제공해요. 제공량과 초과 기준은 바뀔 수 있으니 공식 가격 페이지와 문서에서 현재 표현을 읽어요.

### 무료 한도를 넘으면 서비스가 바로 중단되나요?

항상 그렇다고 단정할 수 없어요. 정책에 따라 초과분이 청구되거나 추가 조치가 필요할 수 있으니, 무료라도 사용량 알림과 예산 기준을 준비해요.

### 대역폭 사용량은 어디서 확인하나요?

프로젝트와 서비스 사용량 화면, 문서의 사용량 안내를 같이 봐요. 청구서가 있으면 대역폭 관련 항목이 잡혔는지도 봐요.

### 캐시를 쓰면 무료 티어에 도움이 되나요?

같은 응답을 반복해서 받는 상황이면 캐시가 전송량을 줄이는 데 도움이 돼요. 규칙이 잘못되면 오래된 응답이 보이니 정적 자산과 API를 구분해 적용해요.

### 무료 티어로 운영 서비스를 돌려도 되나요?

작은 실험이나 개인 프로젝트에는 맞을 수 있어요. 트래픽 변동이 큰 운영 서비스라면 유료 플랜이나 별도 인프라를 같이 검토하는 편이 안전해요.
