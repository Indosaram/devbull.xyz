## 무료 티어 대역폭이 의미하는 것

대역폭은 흔히 “네트워크로 오가는 데이터의 양”을 뜻해요. Koyeb에 배포한 애플리케이션은 사용자의 요청을 받고 응답을 돌려주는데, 이때 HTML, JSON, 이미지, 파일 같은 응답 데이터가 외부로 전송돼요. 이 전송량이 플랫폼의 사용량 계산에 영향을 줄 수 있어요.

여기서 중요한 점은 대역폭이 단순히 “방문자 수”와 비례하지 않는다는 거예요. 같은 방문자라도 응답 본문이 큰 API를 호출하면 전송량이 커지고, 정적 파일을 캐시하면 전송량이 줄어들 수 있어요. 따라서 무료 티어를 오래 쓰려면 방문자 수만 보지 말고 응답 크기와 반복 요청을 함께 봐야 해요.

Koyeb 무료 티어의 대역폭 항목은 공식 가격 페이지에서 확인하는 것이 가장 안전해요. 플랫폼은 요금제와 사용량 정책을 바꿀 수 있으므로, 배포 직전과 운영 중에 주기적으로 공식 페이지를 다시 확인하는 습관이 필요해요. 특히 무료 티어에서 유료 플랜으로 전환되는 조건이나 초과 사용량 처리 방식은 문서마다 표현이 다를 수 있으니, 가격 페이지와 사용량 문서를 같이 봐야 해요.

## 대역폭을 줄이는 운영 방법

무료 티어에서 대역폭을 아끼려면 애플리케이션의 응답을 작게 만드는 것이 기본이에요. 가장 먼저 볼 것은 API 응답 크기예요. 목록 조회에서 모든 필드를 반환하지 말고 필요한 필드만 내려주고, 페이지네이션을 적용하면 한 번의 응답 크기를 줄일 수 있어요.

정적 자산은 캐시와 압축을 함께 적용하는 것이 좋아요. CSS, JavaScript, 이미지처럼 자주 바뀌지 않는 파일은 캐시 기간을 길게 잡고, 텍스트 응답은 압축을 적용해 전송량을 줄일 수 있어요. 다만 캐시를 잘못 설정하면 배포 후에도 이전 파일이 보일 수 있으므로, 파일 이름에 해시를 붙이거나 배포 시 캐시를 무효화하는 전략이 필요해요.

이미지와 동영상은 특히 주의해야 해요. 원본 이미지를 그대로 내려주면 대역폭 사용량이 빠르게 커질 수 있어요. 썸네일을 별도로 만들고, 필요하면 외부 스토리지나 전송 전용 서비스를 사용하는 편이 안전해요. 로그나 모니터링 데이터를 외부로 많이 보내는 구조도 전체 네트워크 사용량에 영향을 줄 수 있으니, 전송 주기와 크기를 함께 점검해야 해요.

마지막으로 불필요한 요청을 줄이는 것도 중요해요. 헬스 체크를 너무 자주 호출하거나, 프론트엔드에서 같은 API를 반복 호출하는 구조라면 캐시나 요청 병합으로 줄일 수 있어요. 무료 티어는 작은 최적화가 누적 효과를 내는 환경이므로, 배포 후에도 응답 크기와 호출 패턴을 주기적으로 확인하는 것이 좋아요.

네, 무료 티어는 플랫폼이 정한 사용량 범위 안에서 대역폭을 제공해요. 정확한 제공량과 초과 기준은 시점에 따라 달라질 수 있으므로 Koyeb 공식 가격 페이지와 문서에서 직접 확인해야 해요.

### 무료 한도를 넘으면 서비스가 바로 중단되나요?

항상 그렇다고 단정할 수 없어요. 플랫폼 정책에 따라 초과 사용량이 청구되거나 추가 조치가 필요할 수 있으므로, 무료 티어라도 사용량 알림과 예산 기준을 준비하는 편이 안전해요.

### 대역폭 사용량은 어디서 확인하나요?

Koyeb 대시보드의 프로젝트와 서비스 사용량 화면, 공식 문서의 사용량 안내를 함께 확인해요. 청구서가 있다면 청구 항목에서 대역폭 관련 과금이 있는지도 같이 봐야 해요.

### 캐시를 쓰면 무료 티어에 도움이 되나요?

네, 같은 응답을 반복해서 내려받는 상황이라면 캐시가 전송량을 줄이는 데 도움이 돼요. 다만 캐시 규칙이 잘못되면 오래된 응답이 노출될 수 있으니 정적 자산과 API 응답을 구분해 적용해야 해요.

### 무료 티어로 운영 서비스를 돌려도 되나요?

소규모 실험이나 개인 프로젝트에는 적합할 수 있어요. 하지만 트래픽 변동이 큰 운영 서비스라면 유료 플랜이나 별도 인프라를 함께 검토하는 것이 안전해요.
