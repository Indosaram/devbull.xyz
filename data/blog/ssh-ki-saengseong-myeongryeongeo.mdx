SSH 키 생성 명령어는 ssh-keygen으로 종류, 경로, 주석을 지정해 개인 키와 공개 키 쌍을 만드는 명령이에요. 공개 키만 서버에 등록하고, 개인 키는 권한이 느슨하면 클라이언트가 거절해요. 같은 경로로 다시 만들면 기존 키를 덮어쓸 수 있어요. 아래는 옵션 의미와 만드는 순서예요.

## 한눈에 보기

기본 저장 위치는 사용자 홈의 ssh 디렉터리예요. 종류는 -t, 경로를 -f, 주석은 -C로 지정해요. 새 서버는 ed25519를 먼저 검토하고, 오래된 장비만 RSA를 봐요. 생성 뒤 공개 키를 authorized_keys에 넣고 개인 키 경로로 접속을 시험해요.

## 키 종류와 옵션 비교

앞 표는 알고리즘 용도, 뒤 표는 옵션 의미예요. ed25519는 신규에 널리 쓰이고, RSA는 호환이 필요할 때, DSA는 새로 만들지 않아요. -N은 암호를 프롬프트 없이 넘기므로 셸 히스토리에 남지 않게 조심해요. -p는 기존 키의 암호를 바꿀 때 써요.

| 키 종류 | 특징 | 이런 경우에 적합 |
| --- | --- | --- |
| ed25519 | 키 길이가 짧고 최근 OpenSSH에서 널리 지원돼요 | 신규 서버 접속, 배포용 키 |
| rsa | 오래된 시스템과의 호환 범위가 넓어요 | 레거시 장비, 오래된 라이브러리 연동 |
| ecdsa | 타원곡선 기반이며 일부 환경에서 사용돼요 | ed25519를 지원하지 않는 상대 시스템 |
| dsa | 현재는 권장되지 않아요 | 신규 사용은 피하는 편이 좋아요 |

| 옵션 | 의미 | 사용 예 |
| --- | --- | --- |
| `-t` | 키 종류를 지정해요 | `-t ed25519` |
| `-b` | 키의 비트 수를 지정해요 | RSA처럼 길이를 조정할 때 |
| `-C` | 키 끝에 붙는 주석을 추가해요 | `-C "deploy-key"` |
| `-f` | 저장할 파일 경로를 지정해요 | `-f ~/.ssh/deploy_key` |
| `-N` | 암호를 프롬프트 없이 전달해요 | 자동화 스크립트에서 사용 |
| `-p` | 기존 키의 암호를 변경해요 | `-p -f ~/.ssh/id_ed25519` |

## 단계별로 키 만드는 방법

종류, 경로, 권한, 등록, 접속 시험 순서로 하면 덮어쓰기와 권한 오류를 피해요.

### 키 종류를 정하고 명령 실행

상대 서버가 받는 알고리즘을 정한 뒤 -t로 지정해요. 비트 수가 필요한 종류만 -b를 검토하고, 값은 그 장비 문서를 따라요. 명령은 매뉴얼의 옵션 순서를 지켜요.

### 저장 경로와 암호 입력

-f로 기존 키와 다른 경로를 주면 덮어쓰지 않아요. 사람용 키는 암호를 걸고, 자동화는 배포 전용 키와 비밀 저장을 같이 봐요. 주석에 용도를 적으면 나중에 폐기가 쉬워요.

### 권한 확인

ssh 디렉터리와 개인 키는 소유자만 쓰게 좁혀요. 그룹이 쓸 수 있으면 클라이언트가 키를 무시해요. 공개 키 파일은 개인 키보다 권한이 넓어도 되지만 개인 키와 바꿔 두지 마세요.

### 공개키를 서버에 등록

공개 키 한 줄을 서버 계정의 authorized_keys에 추가해요. 소유자와 권한이 계정과 맞지 않으면 서버가 무시해요. 개인 키 내용을 서버나 채팅에 붙이지 마세요.

### 접속 테스트와 설정 정리

-i로 그 개인 키를 지정해 접속해 봐요. 성공하면 ssh_config에 호스트별 키 경로를 적어요. 실패하면 서버 인증 로그가 클라이언트 거절인지 서버 거절인지 갈라 줘요.

## 상황별 선택 기준

노트북 접속은 암호 있는 ed25519 하나와 서버별 공개 키 등록이 맞아요. CI는 배포 전용 키를 따로 만들고 할 수 있는 일을 제한해요. 여러 서버는 키를 그룹별로 나눌지 정해 폐기 범위를 줄여요. Windows와 WSL은 홈이 다르니 어느 클라이언트인지 정해요.

## 주의할 점

같은 -f 경로로 다시 만들면 덮어쓸 수 있어요. 공개 키와 개인 키를 바꿔 등록하면 접속이 안 돼요. -N으로 암호를 명령줄에 남기지 마세요. 유출이 의심되면 그 공개 키 줄을 지우고 새 쌍을 만들어요.

## 자주 묻는 질문

저장 위치, 암호, 덮어쓰기, 키를 바꿔 등록했을 때가 반복돼요.

### ssh 키는 어디에 저장되나요?

기본은 홈의 ssh 디렉터리이고, -f로 바꿀 수 있어요. 공개 키는 그 경로에 공개 접미사가 붙은 파일이에요. 서버에 남는 것은 authorized_keys의 공개 키 줄이에요.

### 암호는 꼭 설정해야 하나요?

사람용 키는 거는 편이 좋아요. 입력이 없는 자동화는 전용 키와 비밀 저장, 가능하면 명령 제한을 같이 봐요. 암호가 없어도 등록 위치는 공개 키예요.

### 기존 키가 있는데 새로 만들면 덮어써지나요?

다른 -f 경로면 기존 키는 남아요. 기본 경로로 만들면 덮어쓸지 묻는 경우가 있고, 덮으면 옛 서버 접속이 끊겨요. 새 공개 키를 등록한 뒤 옛 줄을 빼는 순서가 안전해요.

### 공개키와 개인키를 바꿔 등록하면 어떻게 되나요?

서버는 공개 키로 검증하는데 개인 키를 넣으면 인증이 안 돼요. 개인 키가 서버에 남으면 유출이에요. 그 줄을 지우고 공개 키만 다시 넣어요.
