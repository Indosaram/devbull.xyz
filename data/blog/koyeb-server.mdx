Koyeb server는 컨테이너나 빌드팩으로 백엔드를 올리고, 리전, 인스턴스, 스케일, 헬스 체크를 서비스 단위로 정하는 배포 플랫폼이에요. 앱이 주입된 포트를 듣지 않으면 배포가 살아 있지 않아요. 로컬 디스크의 상태는 잠자기와 재배포에 위험해요. 아래는 구성 요소와 이전할 때 깨지는 지점이에요.

## 한눈에 보기

서비스는 이미지, 포트, 시작 명령을 정하고, 인스턴스 유형과 스케일이 런타임을 정해요. 시크릿은 이미지 밖에 두고, 로그는 표준 출력으로 남겨야 수집돼요. 최소 인스턴스를 비우면 유휴 때 내려가 첫 요청이 늦어질 수 있어요. 가격과 무료 조건은 가격 문서를 봐요.

## 구성 요소 비교 표

표는 Service, 인스턴스, 스케일, 리전, 헬스 체크, 볼륨, 환경, 로그가 무엇을 정하는지 담아요. 빌드 메모리가 아니라 런타임 기준으로 유형을 고르고, 여유를 남겨요. 헬스 체크는 인증 없는 가벼운 경로로 나눠요.

| 항목 | 무엇을 정하는가 | 백엔드 관점에서 확인할 점 |
| --- | --- | --- |
| Service | 실행할 이미지, 포트, 실행 명령 | 애플리케이션이 플랫폼이 주입하는 포트 환경 변수를 실제로 바인딩하는지 확인해야 해요 |
| Instance 유형 | CPU와 메모리 조합 | 빌드가 아니라 런타임 기준으로 산정하고, 메모리 여유를 남겨야 해요 |
| Scaling | 최소·최대 인스턴스 수 | 최소를 비워 두면 유휴 시 내려가고, 첫 요청 지연이 생깁니다 |
| Region | 실행 위치 | 데이터 저장 위치와 지연 시간 요구사항을 함께 봐야 해요 |
| Health check | 정상 판정 기준 | 인증이 필요 없는 경량 엔드포인트를 따로 두는 편이 안전해요 |
| Volume | 영속 디스크 | 세션, 업로드 파일, SQLite 같은 로컬 상태가 있는지 먼저 점검해요 |
| Environment | 설정과 시크릿 | 민감한 값을 이미지에 굽지 않고 런타임 주입으로 처리해야 해요 |
| Logs | 관측 | 표준 출력으로 남기는 구조여야 수집이 됩니다 |

## 단계별 배포 방법

컨테이너 친화 정리부터 도메인까지 일곱 단계예요.

### 1. 애플리케이션을 컨테이너 친화적으로 정리합니다

설정은 환경 변수로 받고, 상태는 외부 저장으로 빼요. 프로세스는 포그라운드에서 끝나지 않게 해요. 로컬 파일에만 세션을 두면 재시작 때 사라져요.

### 2. Dockerfile 또는 빌드팩 방식을 고릅니다

런타임이 특이하면 Docker로 고정하고, 표준 언어면 빌드팩이 짧을 수 있어요. 이미지 태그를 고정해야 롤백이 돼요. 시작 명령을 이미지와 서비스 설정에 중복으로 두면 어느 쪽이 이기는지 확인해요.

### 3. Koyeb에 연결하고 서비스를 만듭니다

저장소나 이미지를 연결하고 브랜치와 빌드 방법을 정해요. 서비스 이름과 환경을 문서에 적어요. 잘못된 리전에 만들면 데이터 위치와 어긋나요.

### 4. 환경 변수와 시크릿을 넣습니다

비밀은 시크릿으로, 일반 설정은 변수로 나눠요. 이미지에 굽지 마세요. 빠진 값은 시작 로그의 첫 오류로 보여요.

### 5. 리전, 인스턴스, 스케일링을 정합니다

사용자와 데이터에 가까운 리전을 고르되, 무료나 플랜에서 고를 수 있는 목록을 봐요. 최소 인스턴스를 비우면 잠자기가 켜진 것과 같아요. 최대만 키우고 메모리를 안 보면 기동 중 죽을 수 있어요.

### 6. 배포하고 헬스 체크와 로그를 확인합니다

표준 출력 로그와 헬스 경로를 같이 봐요. 앱이 주입된 포트를 듣는지 확인해요. 배포 이력에서 이전으로 되돌릴 수 있는지도 봐요.

### 7. 도메인과 TLS를 연결합니다

기본 주소로 응답을 본 뒤 사용자 도메인을 연결해요. 인증서 상태가 끝나기 전에 안내하지 않아요. 콜백 URL을 그 도메인과 맞춰요.

## 상황별 선택 기준

이미지가 있으면 Docker 경로, 표준 앱이면 빌드팩을 먼저 봐요. 항상 깨어 있어야 하면 최소 인스턴스를 유지하는 유료 구성을 봐요. 데이터베이스는 외부 관리형에 연결하는 구성이 안전해요. 팀은 리전과 시크릿 권한을 같이 정해요.

## 주의할 점

scale-to-zero를 장애로 오해하지 않게 팀에 알려요. 볼륨이 없거나 제한되면 SQLite와 업로드를 로컬에 두지 마세요. 헬스 체크에 인증을 걸면 정상 앱도 실패예요. 무료 한도는 가격 페이지가 기준이에요.

## 자주 묻는 질문

무료 시작, Docker 없이 배포, 데이터베이스, 잠자기 끄기, 이전 때 깨지는 부분이 반복돼요.

### Koyeb server는 무료로 시작할 수 있나요?

무료 등급이 있는지는 가격 페이지의 현재 안내가 기준이에요. 있어도 잠자기와 유형 제한이 있어요. 상용 상시 운영을 무료만으로 설계하지 마세요.

### Docker 없이도 배포할 수 있나요?

빌드팩으로 저장소를 빌드하는 경로가 있어요. 런타임이 특이하면 Docker가 재현이 좋아요. 어느 쪽이든 포트와 시작 명령은 맞춰야 해요.

### 데이터베이스는 어떻게 연결하나요?

외부 관리형의 연결 문자열을 시크릿으로 넣어요. 로컬 디스크를 데이터베이스로 쓰면 재배포와 잠자기에 위험해요. 리전은 데이터베이스와 가깝게 고르세요.

### scale-to-zero를 끄려면 어떻게 하나요?

최소 인스턴스를 비우지 않고 유지하는 설정이 그 역할이에요. 플랜에서 유지 옵션이 되는지는 문서를 봐요. 끄면 유휴 때도 인스턴스가 남아 비용 구조가 달라질 수 있어요.

### 기존 서버에서 옮길 때 가장 많이 깨지는 부분은 무엇인가요?

고정 포트, 로컬 디스크 상태, 환경 변수 누락, 헬스 체크 인증이에요. 이미지에 비밀을 구워 둔 것도 같이 깨져요. 이전 전에 이 넷을 체크리스트로 지우세요.
