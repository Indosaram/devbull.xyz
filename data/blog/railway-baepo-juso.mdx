Railway 배포 주소는 프로젝트 화면에서 대상 서비스를 선택한 뒤 공개 네트워킹 설정에서 확인하는 것이 가장 빠릅니다. 서비스에 공개 도메인이 생성되어 있어야 하며, 사용자 지정 도메인을 연결한 경우에는 그 주소를 함께 관리해야 합니다. 이 글은 대시보드에서 주소를 찾는 절차와 상황별 선택 기준을 정리합니다.

## 한눈에 보기

Railway에서 흔히 말하는 배포 주소는 서비스에 연결된 공개 도메인을 뜻합니다. 프로젝트 전체에 하나만 붙는 값이 아니라 서비스 단위로 확인해야 하며, 같은 프로젝트 안에서도 서비스마다 주소가 다를 수 있습니다. 공개 네트워킹이 꺼져 있으면 외부에서 접근할 주소가 생기지 않으므로, 먼저 대상 서비스와 환경을 정확히 선택하는 것이 중요합니다.

| 확인 위치 | 보이는 값 | 주로 쓰는 상황 |
|---|---|---|
| 프로젝트 캔버스의 서비스 타일 | 서비스 이름과 배포 상태 | 주소를 확인할 대상 서비스 선택 |
| 서비스 설정의 공개 네트워킹 | 플랫폼 제공 도메인 | 빠르게 외부 접근 주소 확인 |
| 사용자 지정 도메인 목록 | 연결한 도메인과 검증 상태 | 운영 도메인 점검 |
| 배포 상태와 로그 | 최근 배포 성공 여부 | 주소 응답 문제의 원인 파악 |

표에서 알 수 있듯이 배포 주소를 찾는 일과 서비스가 정상적으로 배포되었는지 확인하는 일은 함께 봐야 합니다. 도메인이 보이더라도 최근 배포가 실패했다면 주소는 존재하지만 응답이 정상적이지 않을 수 있습니다. 반대로 배포가 성공했어도 공개 네트워킹이 비활성화되어 있으면 외부 주소는 보이지 않습니다.

## 배포 주소와 공개 도메인의 차이

Railway 공식 문서는 외부에서 서비스에 접근하는 기능을 공개 네트워킹으로 설명합니다. 대시보드에서 보이는 주소는 이 공개 네트워킹 설정의 결과로 생성된 도메인입니다. 따라서 배포 주소를 확인하려면 먼저 해당 서비스가 외부 공개를 허용하고 있는지 확인해야 합니다.

플랫폼이 제공하는 도메인은 Railway가 서비스에 기본으로 연결해 주는 주소입니다. 빠르게 동작을 확인하거나 테스트용으로 공유할 때 편리합니다. 반면 사용자 지정 도메인은 운영 브랜드에 맞는 주소를 직접 연결한 것으로, DNS 설정과 검증 절차가 추가로 필요합니다. 두 주소는 같은 서비스를 가리킬 수 있지만 관리 위치와 용도가 다릅니다.

또한 Railway에서는 프로젝트 안에 여러 환경과 서비스가 존재할 수 있습니다. 운영 환경의 서비스와 스테이징 환경의 서비스가 별도로 구성되어 있다면 각각의 공개 도메인을 확인해야 합니다. 다른 환경을 선택한 상태에서 주소를 찾으면 실제 운영 주소가 아닌 테스트 주소를 보게 될 수 있으므로, 화면 상단의 프로젝트와 환경 표기를 함께 확인하는 습관이 좋습니다.

## 대시보드에서 확인하는 단계

대시보드에서 배포 주소를 확인하는 흐름은 다음과 같습니다. 화면의 메뉴 이름과 버튼 표기는 시점에 따라 조금 달라질 수 있으므로, 공개 네트워킹 또는 도메인이라는 표현을 기준으로 찾으면 됩니다.

- Railway에 로그인하고 주소를 확인할 프로젝트를 엽니다.
- 프로젝트 캔버스에서 배포 주소를 확인할 서비스를 선택합니다.
- 서비스 설정에서 공개 네트워킹 또는 도메인 관련 항목을 찾습니다.
- 아직 도메인이 없다면 도메인 생성 동작을 실행합니다.
- 화면에 표시된 도메인을 복사해 브라우저나 터미널에서 응답을 확인합니다.

도메인 생성 후에는 서비스가 사용하는 내부 포트와 공개 주소가 올바르게 연결되었는지 확인해야 합니다. 애플리케이션이 외부 요청을 받을 수 있는 상태인지, 헬스 체크 경로가 정상인지도 함께 보는 것이 좋습니다. 주소가 보인다는 사실만으로 애플리케이션까지 정상이라고 단정하지 말고, 실제 요청과 응답을 확인하는 단계를 거치는 편이 안전합니다.

사용자 지정 도메인을 연결한 경우에는 도메인 목록에서 검증 상태를 확인합니다. DNS 레코드를 추가한 직후에는 검증이 끝나지 않을 수 있으므로, Railway가 안내하는 레코드 값을 그대로 적용했는지 다시 확인합니다. DNS 제공업체마다 설정 화면이 다르므로, 레코드 이름과 값을 복사해 붙여 넣는 방식이 오류를 줄이는 데 도움이 됩니다.

## 상황별 선택

### 빠르게 외부에 공개할 때

테스트나 데모 목적으로 빠르게 주소를 만들고 싶다면 플랫폼이 제공하는 도메인을 사용하는 편이 간단합니다. 서비스 설정에서 공개 네트워킹을 활성화하고 도메인을 생성하면 별도의 DNS 작업 없이 주소를 확인할 수 있습니다. 다만 이 주소는 운영 브랜드와 무관하므로 외부 공유 범위를 신중히 정해야 합니다.

### 운영 도메인을 따로 쓸 때

사용자에게 공개할 서비스라면 사용자 지정 도메인을 연결하는 것이 일반적입니다. Railway가 안내하는 DNS 레코드를 도메인 제공업체에 추가하고, 검증이 완료되었는지 확인합니다. 이때 플랫폼 도메인과 사용자 지정 도메인이 모두 같은 서비스를 가리키도록 설정되어 있는지도 점검하는 것이 좋습니다.

### 환경을 분리해 운영할 때

운영 환경과 테스트 환경을 나누어 사용한다면 각 환경의 서비스에 서로 다른 도메인을 연결하는 것이 관리에 유리합니다. 운영 주소와 테스트 주소를 구분해 두면 배포 후 확인할 대상이 명확해집니다. 환경 변수와 외부 연동 설정도 주소에 맞게 분리되어 있는지 함께 확인해야 합니다.

## 주의할 점

- 공개 네트워킹이 꺼져 있으면 배포 주소가 보이지 않을 수 있습니다.
- 서비스가 배포되지 않았거나 빌드에 실패하면 도메인이 있어도 정상 응답하지 않을 수 있습니다.
- 사용자 지정 도메인은 DNS 설정과 검증에 시간이 걸릴 수 있으므로 즉시 반영된다고 가정하지 않는 것이 좋습니다.
- 다른 환경이나 다른 서비스를 선택한 상태에서 주소를 확인하면 운영 주소와 다른 값을 볼 수 있습니다.
- 공개 도메인은 외부에서 접근할 수 있으므로 인증, 접근 제어, 비밀 값 노출 여부를 함께 점검해야 합니다.
- 도메인을 변경하거나 새로 생성할 때는 환경 변수, 콜백 주소, 외부 연동 설정도 함께 갱신해야 합니다.

배포 주소를 확인한 뒤에는 단순히 화면에 보이는 문자열만 기록하지 말고, 어떤 서비스와 어떤 환경에 연결된 주소인지 함께 남겨 두는 것이 좋습니다. 운영 중 주소가 바뀌면 장애 대응 속도에 영향을 줄 수 있으므로 변경 이력을 관리하는 편이 안전합니다.

## 자주 묻는 질문

### Railway 배포 주소는 어디에서 확인하나요?

프로젝트 화면에서 대상 서비스를 선택하고 설정의 공개 네트워킹 항목을 열면 확인할 수 있습니다. 아직 도메인이 없다면 같은 화면에서 도메인 생성을 실행해야 합니다.

### 도메인이 보이지 않을 때 무엇을 확인해야 하나요?

서비스가 정상 배포되었는지, 공개 네트워킹이 켜져 있는지, 올바른 환경과 서비스를 선택했는지 확인해 주세요. 그래도 보이지 않으면 프로젝트 권한과 최근 설정 변경 이력을 점검하는 것이 좋습니다.

### 사용자 지정 도메인과 플랫폼 도메인은 어떻게 다른가요?

플랫폼 도메인은 Railway가 제공하는 기본 주소이고, 사용자 지정 도메인은 운영 브랜드에 맞게 연결한 주소입니다. 사용자 지정 도메인은 DNS 설정과 검증 절차가 추가로 필요합니다.

### 배포할 때마다 주소가 바뀌나요?

일반적으로 서비스에 연결한 공개 도메인은 서비스 단위로 유지됩니다. 다만 도메인을 삭제하거나 새로 생성하면 주소가 달라질 수 있으므로 운영 환경에서는 변경 이력을 관리해 주세요.
