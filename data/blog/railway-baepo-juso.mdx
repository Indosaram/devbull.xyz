## 한눈에 보기

배포가 성공해도 공개 주소가 자동으로 의미 있는 운영 도메인이 되지는 않아요. 서비스마다 플랫폼 도메인을 붙여 빠르게 확인하고, 운영에는 사용자 도메인을 연결하는 구성이 흔해요. 주소는 프로젝트의 서비스 설정과 네트워킹 화면에 있어요. 환경이 나뉘면 주소도 환경마다 달라질 수 있으니, 스테이징 주소를 운영 문서에 적지 않도록 이름을 구분해요.

| 확인 위치 | 보이는 값 | 주로 쓰는 상황 |
|---|---|---|
| 프로젝트 캔버스의 서비스 타일 | 서비스 이름과 배포 상태 | 주소를 확인할 대상 서비스 선택 |
| 서비스 설정의 공개 네트워킹 | 플랫폼 제공 도메인 | 빠르게 외부 접근 주소 확인 |
| 사용자 지정 도메인 목록 | 연결한 도메인과 검증 상태 | 운영 도메인 점검 |
| 배포 상태와 로그 | 최근 배포 성공 여부 | 주소 응답 문제의 원인 파악 |

## 배포 주소와 공개 도메인의 차이

플랫폼 도메인은 배포 직후 동작을 확인할 때 편해요. 사용자에게 안내할 이름은 보통 직접 보유한 도메인이에요. 둘 다 같은 서비스로 향할 수 있지만, 인증서와 DNS, 공개 범위는 따로 봐요. 표는 확인 위치와 언제 어느 쪽을 쓰는지 나눠 둔 거예요. 내부 통신만 필요하면 공개 주소를 열지 않는 선택도 있어요.

## 대시보드에서 확인하는 단계

프로젝트에서 해당 서비스를 연 다음 네트워킹 또는 설정 영역의 도메인 목록을 봐요. 배포 로그가 성공인지 먼저 보고, 그다음 공개 포트와 도메인 생성 여부를 확인해요. 사용자 도메인이면 안내에 나온 레코드를 DNS에 넣었는지, 대상 서비스가 맞는지 봐요. 환경 전환 탭이 있으면 지금 보는 환경이 운영인지 스테이징인지 확인해요. 주소가 있는데 응답이 없으면 헬스 체크와 앱이 듣는 포트를 이어서 봐요.

## 상황별 선택

목적에 따라 열어 둘 주소가 달라요. 아래 세 경우는 공개 범위만 바꿔도 운영 실수가 줄어요.

### 빠르게 외부에 공개할 때

플랫폼이 주는 도메인으로 먼저 열어요. 빌드와 시작 명령, 환경 변수가 맞는지 이 주소로 확인한 뒤 사용자 도메인을 붙여요. 임시 주소라도 인증이 없는 API라면 테스트 데이터만 두세요.

### 운영 도메인을 따로 쓸 때

보유한 도메인을 서비스에 연결하고, DNS 레코드는 문서에 안내된 대상만 넣어요. 플랫폼 도메인을 계속 열어 둘지 팀 규칙으로 정해요. 인증서 발급이 끝나기 전에 사용자를 안내하면 접속 실패로 보여요.

### 환경을 분리해 운영할 때

스테이징과 운영의 도메인 이름을 다르게 둬요. 환경 변수의 공개 URL도 그 이름과 맞추지 않으면 콜백과 리다이렉트가 다른 환경으로 새요. 배포할 때마다 주소가 바뀌는지보다, 어느 환경의 주소인지를 문서에 고정하는 편이 중요해요.

## 주의할 점

도메인 생성 전에 서비스가 비공개면 목록이 비어 보일 수 있어요. 사용자 도메인의 DNS를 잘못된 서비스에 연결하면 배포는 성공인데 다른 앱이 열려요. 와일드카드나 경로 규칙은 문서 범위를 넘지 않게 최소로 시작해요. 주소를 바꿨으면 외부에 알려 둔 문서, OAuth 콜백, 웹훅 등록도 같이 고쳐요.

## 자주 묻는 질문

주소가 어디 있는지, 왜 안 보이는지가 대부분이에요.

### Railway 배포 주소는 어디에서 확인하나요?

서비스의 네트워킹 또는 도메인 설정에서 봐요. 배포 로그만 성공이어도 공개 도메인을 아직 안 만들었으면 주소가 없을 수 있어요. 공식 공개 네트워킹 문서의 화면 이름과 맞춰 보면 헷갈리지 않아요.

### 도메인이 보이지 않을 때 무엇을 확인해야 하나요?

배포가 실제로 끝났는지, 서비스를 잠시 멈춘 상태는 아닌지, 지금 환경이 맞는지부터 봐요. 사용자 도메인이면 DNS 레코드와 연결 대상 서비스를 확인해요. 생성 버튼이 비활성인지 플랜과 권한도 같이 봐요.

### 사용자 지정 도메인과 플랫폼 도메인은 어떻게 다른가요?

플랫폼 도메인은 빠르게 확인하는 이름이고, 사용자 도메인은 직접 보유한 이름을 DNS로 연결한 거예요. 인증서와 DNS 책임이 달라요. 운영 안내는 사용자 도메인 기준으로 쓰는 편이 좋아요.

### 배포할 때마다 주소가 바뀌나요?

한 번 연결한 도메인 이름 자체가 배포마다 바뀌는 구조는 아니에요. 다만 서비스를 지우고 다시 만들거나 환경을 바꾸면 다른 주소가 생길 수 있어요. 고정해야 하는 이름은 사용자 도메인으로 두고, 환경 변수에도 그 이름을 적어요.
